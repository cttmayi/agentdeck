# 工作流智能体组：它是怎么工作的

> 一句话：**一个组 = 「执行 → 审核 → 行动」这条链的一份配置。**
> 建任务时选了组，这条链就定了；选中之后，跑的还是原来那条链路。
>
> ⚠️ **2026-10：组是这条链的唯一出处。** "谁审谁"与"判完允许动什么"以前也能配在
> 单个智能体上（执行者身上一个"由谁审它"、审核者身上一份行动权限）。那两个字段
> **已经整个撤掉**了——所以现在的规则只有两条：
>
> - **选了组** ⇒ 审核者与行动权限都是组的（还能按这一次单独覆盖）；
> - **没选组**（选单个智能体）⇒ **这条任务没有审核者**：产出不会被审、也不会有判决
>   （建任务页的摘要会直接把这句话写出来）。

---

## 1. 组里装了什么

| 组上的东西 | 含义 |
|---|---|
| **执行者** | 谁干活 |
| **审核者** | 谁把关 |
| **行动权限** | 判过之后允许触发哪些动作（含固定参数、调试动作） |
| **返工次数** | 审核不通过时，最多让它重做几次（0–100，或"无限"） |

当前形态固定是**恰好 1 个执行者 + 1 个审核者**，由成员各自的角色决定；
别的形态（多执行者分工、多审核者会签）还没有实现，写不进去。

成员有两种来源：**选已有的**（全局智能体）或**新建私有**（只属于这个组，
不进智能体列表，删组时一起删）。

---

## 2. 三步：执行 → 审核 → 行动

```
       ①执行                ②审核                ③行动
   ┌───────────┐      ┌───────────┐      ┌───────────┐
   │  执行者    │ ───▶ │  审核者    │ ───▶ │ 判过且带动作 │
   │  动手干活  │ 产出 │  给出判决  │ 通过 │  平台执行   │
   └───────────┘      └───────────┘      └───────────┘
                            │
                       不通过 │ 还有返工额度
                            ▼
                      交回执行者重做 ──▶ 再审核（循环）
```

- **① 执行**：执行者拿到任务、干活、交付产出。组**不改变**它看到的任务内容。
- **② 审核**：审核者拿到产出 + **这一次允许哪些动作**，必须给出一个判决。
- **③ 行动**：只有"通过**且**带动作"才会真的做点什么；通过了但没动作，就只记录。

---

## 3. 建任务时发生了什么

选了组之后，daemon 在写下这条任务之前把组**摊开成普通配置**：

- **执行者由组决定**——请求里写了别人就报错（"选了组又指定别人执行"是矛盾的意图，不猜）。
- **其余字段是覆盖**：请求里没给就用组的，给了就用这次的（换审核者、改动作、改返工次数都可以）。
- **摊开之后，组就退场了**：任务身上只留一个组 id 作记录。所以**改一个组，不影响已经派出去的任务**——它只影响以后的默认。

可选的组要过四道闸：组还在、没被停用、形态是 1 执行 + 1 审核、执行者对得上。

---

## 4. 审核与判决

**审核者从哪来**：**组的审核者**（组里那个审核角色成员）。任务级的"这一次换个人审"仍然可用，
但那是一条只对这一次有效的覆盖，不改组的默认。

**没有组就没有审核者**（2026-10）。以前"没选组"会去读执行者身上那条「由谁来审它」，
那个字段撤掉之后这条路上谁也不审——所以建任务页**必须把这句话说出来**
（"没有——选单个智能体不会自动审核；要审核请改选一个智能体组"），
否则使用者看到的摘要与选组那条只差一行，而那一行恰恰是"你的产出不会有人看"。

如果这次明确选了"不自动审核"，同样不审，但那是**一条记录**（库里写的是 `null`，
日志说的是"这是你选的"），与"没选组"区分得开：**这是决定，不是配置错误**，不打扰任何人。

**审核者拿到什么**：产出（正文截断到两万字）＋ 落盘的产出文件，外加一份**动作清单**——
它只能引用清单里的动作，否则判决作废（所以清单必须如实传给它，不能空着）。

**判决是闭合的**：结论只有三种，外加一个理由码和逐条发现（每条能指回产出的位置）。

| 结论 | 接下来 |
|---|---|
| **通过 + 带动作** | ③ 行动：平台执行那个动作 |
| **通过 + 不带动作** | 只记录（"通过，没有要做的事"） |
| **不通过** | 交回执行者重做（还有额度）；额度用完就交给人 |
| **需要人判断** | 交给人（进通知中心，等你处理） |

判决本身也是一条有终态的记录：一次"不通过"派出一条返工任务之后，这条判决的故事就到此为止；
重做的是**新的那条任务、新的那份判决**。

---

## 5. 返工闭环（这段最有特色）

审核不通过时，平台**不是**把产出丢给下一个人，而是**交回同一个执行者原地改**：

- **同一个工作目录**——它是"在原地改"，不是另起一摊（否则看不见上次干了什么）。
- **接着上次的会话**——不用从零再来一遍。
- **提示词说清来历**：先说明"上一次的产出没有通过审核"，再把**结构化的审核意见**给它
  （理由码 + 逐条发现 + 每条的证据指向）——少了证据指向，它只能猜"你说的是哪一段"。

**返工几次怎么算**：不另存计数器。每条返工任务都在链条深度上 +1，
所以"已经几次"就是那条任务的深度，"允许几次"来自组（或这次任务的覆盖）：

| 设置 | 行为 |
|---|---|
| `0`（或不配） | 不返工：不通过就直接交给人 |
| `1–100` | 最多重做这么多次，用完再交给人 |
| **无限** | 一直重做，直到通过或需要人判断（**会持续烧 CLI 额度，慎用**） |

**额度用完之后**：判决落到"交给人"并进通知中心，标题直说原因
（"审核不通过且返工次数已用完（5 次）"）。⚠️ 这里**绝不会**显示成"已完成审查"——
一条被否决的任务装成已完成，是这套链路最不能犯的错。

---

## 6. 行动

只有判决能触发动作，而且**默认自动执行**，不等人批准。

动作只可能来自**已安装的工具包**（工具脚本只能改工作目录里的东西，没有平台 API）。
参数分三份，模型只看得见其中一份：

| 来源 | 谁给的 | 模型能改吗 |
|---|---|---|
| 开放参数 | 模型写在判决里 | ✅ |
| 绑定参数 | 平台按事实注入 | ❌ |
| **固定参数** | **使用者在组的「行动权限」里钉的** | ❌（写了判决就作废） |

勾了**调试**的动作不跑脚本，只记录动作与解析后的参数——用来先看清"它会做什么"。
动作失败不会被吞掉：进失败状态并发通知。

---

## 7. 几道边界

- **链条有深度上限**（5 层）。超了就停止继续派生并通知你，避免"改 → 审 → 再改 → 再审"烧钱。
- **审核者没了 / 角色被改了**：不硬跑（否则"审核结论看着正常"但其实是假的），
  跳过并发通知——因为那是"配置过、现在失效了"，产出没被审而状态一切正常。
- **报告审核只能给结论**：报告不属于任何组，所以这条路上**一个动作都不允许**
  （判决里带动作会被拦下、交给人）。动作是"这条链"的权限，不是审核者个人的。
- **判决格式不合规**：可能修好的（忘了写围栏）重试一次；**修不好的**（引用了不存在的动作）
  直接交给人，不重复烧 token。
- **组停用**只是"建任务时不可选"，不删历史；组里的私有成员只能随整组一起删。
- 组**没有**"运行中改组"这回事：改的是以后的默认。

---

## 8. 界面上看到什么

- **智能体组页**（动作权限在这里配，智能体页不再有那一栏）：表单从上到下就是那条链，
  三个阶段各有编号头——
  **① 执行 · 谁来做这件事** → **② 审核 · 谁把关，不过就返工**（返工次数跟着这一步）
  → **③ 行动 · 判完可以触发哪些动作**。模式那一栏写着"工作流"。
- **建任务页**：一个「智能体 / 智能体组」的切换。选组后执行者由组决定、审核者与动作
  都取组的、返工次数也取组的；右侧摘要逐行显示**执行者 / 审核者 / 动作 / 返工**
  （★ 2026-10：选单个智能体那一档，摘要里"审核者"那一行写的是
  "没有——选单个智能体不会自动审核"，**不是不画**——不画等于把这件事藏起来）。
- **任务详情与看板**：阶段由任务链推导（执行中 / 待人工 / 已审查…），
  **"返工过几次"**就是数了几条"重做过"的任务。
