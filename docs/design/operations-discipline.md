# 操作纪律（D66 Chrome 事故后固化，2026-10）

> 目的：把散落在各处的"教训"收拢成一页，**每次动这台机器前过一遍**。
> 这些规则不是新规定——每一条都来自仓库里真实发生过的事故，附来源。
> 违反规则造成的损失是使用者的（本机浏览器、数据、时间），不是我的。

## 1. 杀进程：只按本次专属标识匹配，绝不宽匹配

- ✅ 只 kill 自己启动的 headless Chrome：按 `--user-data-dir=$PWD/.cache/...`
  或 `--headless` 匹配；或按启动时记录的 PID。
- ❌ **禁止** `pkill -f "Google Chrome"`——会连使用者本人的浏览器一起杀。
- 事故记录：2026-09-13 首次（`tools/layout-probe/README.md`「四个坑」第 3 条，
  已提交 8bd2fb35/f03ee2f1）；**2026-10 D66 复发**（本会话截图清理时再次
  `pkill -f "Google Chrome"`，规则明明已提交在案——教训：记录要查，不是要记得）。

## 2. headless Chrome 不自己退出

- `--dump-dom` / `--screenshot` 打完会**挂住**：必须"后台跑 → 轮询输出文件 →
  再精确杀"，不能等它自然结束（来源：`tools/layout-probe/README.md`）。

## 3. 探针（probe.html 内联脚本）

- 整个内联脚本是一个作用域：**`const` 不能重名**，否则整段语法错误，症状像
  "Chrome 超时"（`#out` 还是 pending、零 error）。
  加检查后用 `node --check` 过一遍提取出的脚本（来源：README「四个坑」）。
- 探针要**收拾自己的现场**：localStorage 状态（如任务视图列表/看板模式）会带到
  下一轮，切视图前显式还原（来源：README，D39 事故）。

## 4. 改代码前先读判据（探针 + 文档）

- D66 教训：git HEAD 的智能体 runtime 卡是 3 行旧版、工作树是极简 1 行版，
  凭印象抄结构差点把旧版抄回来——**先查 probe 怎么量，再决定结构**。

## 5. 大块结构替换：行首锚定，不用子串

- D66 教训：`s.index('  </section>')` 会命中 8 空格缩进的内层闭合（substring
  命中）——替换 `<section>` 级结构用 `^\s{2}</section>` 行首锚定 + 校验内容。

## 6. 只写仓库内 + 收尾

- 数据、Chrome profile、DOM 全在 `.cache/`；临时 harness HTML（`_*test*.html`）
  用完删；不往用户目录（`~/Library/...`）写任何东西。

## 7. 变更纪律（D 系列一贯）

- 每个改动：typecheck → build（记 js+css 合并 md5）→ test → probe 全绿 →
  红证（变异 → 红 → 恢复 → md5 一致）→ 文档；报告给实测证据（来源：
  `docs/design/architecture.md` §12.4、`docs/srs/requirements.md` §11.6）。

## 8. 界面改动的沟通与布局纪律（2026-11 智能体详情页五连改后固化）

> 一次"独有技能摆哪"连着改五轮，五轮里每一轮都犯了下面至少一条。
> 使用者拍板：这五条写进纪律。每一条的"事故"都是同一批 UI 改动。

### 8.1 用户描述现状 / 问"为什么"时，先复述理解或先解释，不默认动手改

- 事故 1：使用者说"还是上面勾选的样子，只显示名字"——那是**现状描述**
  （"要的就是这种样子"），我当成批评，改成两行条目（名字+摘要），一轮白改；
  使用者澄清"我就是要显示成『勾选 名字』的样子"。当时使用者还说过"如果
  不理解，先解释给我听"——我没用。
- 事故 2：使用者问"为什么有 2 个名字？"——问"为什么"不等于要改；我直接改成
  "只显示名字"，违反"与同类一致"，使用者纠正"我要的是和上面的一致，不要
  不同行为"。
- ✅ 描述现状/疑问的句子，先确认"是要改成这样，还是这样就行"；问"为什么"
  先回答原因。
- ❌ 不要因为"用户提到某个现象"就默认它是个待修 bug。

### 8.2 删界面元素 ≠ 删功能；显示逻辑默认与同类一致

- 事故：使用者说"也不需要『独有技能』这些文字……也不需要新增按钮"——我连
  新增入口的代码（编辑器新增态、slug 空校验、7 个词条键）一起删了，界面从此
  没有新增独有技能的能力（只剩文件/API）。"不需要按钮"是**隐藏入口**，不是
  移除能力。
- ✅ 删按钮/入口前，确认功能本身要不要留；显示逻辑（如名字旁补 slug）默认
  与同类控件完全一致，不一致要有理由。
- ❌ 把"界面元素"的删减顺手做成"功能"的删减。

### 8.3 改布局要保住既有意图：对照旧探针判据逐条核对，意图没变判据不删

- 事故 1（框高度）：把边框从 `.skill-picker` 挪到新容器 `.skill-box` 时丢了
  "与指令框同高"的意图——旧布局靠 `flex: 1 + max-height: 22rem`（22rem ≈
  指令框高）实现；新容器只带了 `flex: 1`，框比指令框高 49px，使用者报
  "框的高度不对了"。同一轮我还**删掉了**探针里"两个框同高"的判据
  （`pickerFillsCell`），于是探针绿着、肉眼红着。
- ✅ 移动/重构布局时，先列出旧探针判据钉住的**意图清单**，逐条在新结构上
  重新量一遍（量法可以换，意图没变判据不能删）。
- ❌ 结构变了就顺手删判据——那是把"意图"也一起删了。

### 8.4 UI 文案默认不加解释文字

- 事故：详情页堆了指令提示、记忆关闭提示、空态文字等解释；使用者
  "解释文字太多，都去掉……发现你特别喜欢写很多解释文字，请不要这样"。
  这不是第一次——第 254 批使用者就说过"文字解释太多，不需要写那么细致"，
  仍然默认加文案。
- ✅ 新文案默认不加；要加先问"这句必要吗"。保留的只有功能必需：结果/错误
  反馈、防误操作提示、指路（有测试钉着的）。
- ❌ 把"把行为说清楚"当默认——重复反对过的类型直接进禁区。

### 8.5 被问数据/行为先查代码；移动 CSS 检查所有相关规则

- 事故 1：使用者问记忆放哪，我凭印象答"workspace 级、智能体共享"——错的；
  模型上一直按 agent 归属，只是存储放错层（D112 因此发起）。被问时没查代码。
- 事故 2（黑色虚线框）：把边框简写从 `.skill-picker` 挪走时，漏了另一条
  只写 `border-style: dashed` 的规则——它失去配套的 width/color 后回落
  默认值（medium + currentColor），内置智能体框内多出一个黑色粗虚线框。
- ✅ 被问到数据位置/行为细节，先查代码再答；移动样式时搜该元素**所有**
  相关规则（简写 + 单属性分散两处都要看），改完用真实数据截图肉眼确认。
- ❌ 凭印象回答数据问题；只改"看到的"那条规则。
