2. 形态：就是今天那个 FileViewer，一条属性都不删

⚠️ 两处更正（都是我看漏了现有实现）： ① 文件是**弹出**的（FileViewer 内部就是 Modal size="wide"）， 不是固定的两栏；② 它今天就有**两面切换**——渲染 / 原文 （.fv-toggle 里那两颗 data-face-rendered / data-face-raw），另外还有「复制原文」。

所以编辑**只挂在「原文」那一面**：face === 'raw' 时才出现「编辑」； 渲染面（Markdown / 高亮 / HTML 预览 / 图片）永远只读——它本来就不是给你改的地方， 而且 HTML 预览走 sandbox allow-scripts，编辑态更不能和它混在一个面上。 二进制与音视频没有「原文」面（hasFace 就是这么判的）⇒ 它们天然没有编辑。

工具条（.fv-bar）里多加一颗「编辑」；进编辑态之后变成「还原 / 保存」。 渲染面（Markdown / 高亮 / HTML 预览 / 十六进制）一个都不动——编辑态只是"文本面"， 保存失败的原话就留在浮层里（不关窗、不跳走）。

5. 限制只有通用的几条（没有"这个文件不许改"的特例）

限制怎么判为什么
只收 UTF-8 文本读回来非文本 / 二进制 ⇒ 拒绝并说明与技能安装"只收文本"同一口径；十六进制那一面仍可看
大小上限与技能上限同一个数（256 KB）；超了不落盘、说清多少字节超限写下去，注入 / 读取那一侧会炸在一个很远的地方
路径必须待在 scope 目录里拒 ..、绝对路径、\ 开头、盘符与技能支持文件同一道防线
.json 必须能 parseJSON.parse 失败 ⇒ 不落盘，原话 + 位置回显只查**格式**；语义（谁引用谁）不查
.jsonl 每一行都要能 parse逐行 JSON.parse，第 N 行坏 ⇒ 报第 N 行、不落盘append-only 日志的形状是"一行一条"，坏一行整份读不出来
原子写tmp → fsync → rename半截文件 = 读到坏数据

⚠️ **没有**按文件名开的白名单 / 黑名单：agent.json、memory.jsonl、 migrations.json 都**能改**——只过上面那几条通用检查（格式、编码、大小、路径）。 也就是说 id 这类引用键**允许被手改**，改坏了引用会断——平台不拦， 只保证"你写进去的是合法 JSON"。这是使用者的决定（"只有通用限制，不需要特殊限制"）。

6. 接口：把已有的那对端点 scope 化

PUT /api/fs/<scope>/file {text}     ← 白名单 + 校验 + 原子写（二期）
scope ∈ agent:<id> | workflow:<id> | wf-agent:<wid>/<aid> | skill:<名字> | run:<id> | conversation:<id>
