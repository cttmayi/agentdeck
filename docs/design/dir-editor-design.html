目录 / 文件编辑器 草稿 v1 · 待拍板

一句话：**打开一个目录（按 scope 解析），左树右文件；正文类文件直接编辑保存， 结构化文件改完先过 schema 校验，账本与日志只读。** 不是新造阅读器——是 WorkDirTree + FileViewer + GET …/files 这条已有链的扩展（换 scope、加一个 PUT）。

入口scope打开哪个目录能干的事

2. 形态：就是今天那个 FileViewer——**原文面直接就能编辑**，没有"编辑态"

两处更正：① 文件是**弹出**的（FileViewer 内部就是 Modal size="wide"）， 不是固定两栏；② 它今天就有**两面**——渲染 / 原文，还有「复制原文」。 但编辑**不另开一个模式**：原文面本身就是可编辑的文本框，渲染面照旧只读。 ——没有「编辑」按钮、没有"编辑态"，就是那一面能改。

于是工具条只多一颗「保存」（有改动才亮）：路径 · 大小 · [渲染 | 原文] · 复制原文 · 保存 · 关闭。 渲染面那一侧没有「保存」；二进制 / 音视频没有原文面 ⇒ 天然没有编辑与保存。

5. 限制只有通用的几条（没有"这个文件不许改"的特例）

限制怎么判为什么
只收 UTF-8 文本读回来非文本 / 二进制 ⇒ 拒绝并说明与技能安装"只收文本"同一口径；十六进制那一面仍可看
大小上限与技能上限同一个数（256 KB）；超了不落盘、说清多少字节超限写下去，注入 / 读取那一侧会炸在一个很远的地方
路径必须待在 scope 目录里拒 ..、绝对路径、\ 开头、盘符与技能支持文件同一道防线
.json 必须能 parseJSON.parse 失败 ⇒ 不落盘，原话 + 位置回显只查**格式**；语义（谁引用谁）不查
.jsonl 每一行都要能 parse逐行 JSON.parse，第 N 行坏 ⇒ 报第 N 行、不落盘append-only 日志的形状是"一行一条"，坏一行整份读不出来
原子写tmp → fsync → rename半截文件 = 读到坏数据

⚠️ **没有**按文件名开的白名单 / 黑名单：agent.json、memory.jsonl、 migrations.json 都**能改**——只过上面那几条通用检查（格式、编码、大小、路径）。 也就是说 id 这类引用键**允许被手改**，改坏了引用会断——平台不拦， 只保证"你写进去的是合法 JSON"。这是使用者的决定（"只有通用限制，不需要特殊限制"）。

6. 接口：把已有的那对端点 scope 化
