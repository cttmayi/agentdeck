5. 哪些能改（这张表就是实现范围）

文件能改吗为什么
instructions.md、skills/<名>/SKILL.md、main.js、task.md✅ 正文直接改磁盘为准，与技能的 frontmatter 规范化同一条链
agent.json / workflow.json / schedule.json⚠️ 校验后写里面有 id 与引用键，写坏了 run / issue 全指空
agent.json 的 name❌ 拒绝D231：目录名 = 名字的 slug，改名要搬目录 ⇒ 走正规入口
memory.jsonl、log/*.jsonl、migrations.json❌ 只读append-only 日志与平台账本
二进制 / 非 UTF-8❌ 拒绝并说明与技能安装"只收文本"同一口径；十六进制那一面仍可看

6. 接口：把已有的那对端点 scope 化

GET /api/fs/<scope>/files?dir=      ← 一层目录（与 /api/runs/:id/files 同一份实现）
GET /api/fs/<scope>/file?path=      ← 一个文件的文本（FileViewer 已有三面渲染）
PUT /api/fs/<scope>/file {text}     ← 白名单 + 校验 + 原子写（二期）
scope ∈ agent:<id> | workflow:<id> | wf-agent:<wid>/<aid> | skill:<名字> | run:<id> | conversation:<id>

7. 明确不做 / 待拍板

新建 / 删除 / 改名文件一期不做（独有技能的新增删除仍走"放进目录 + 刷新"或正规入口）
在浏览器里执行脚本 / html 预览仍走 sandbox allow-scripts，**绝不加 allow-same-origin**
智能体页那个"独有技能"专用编辑器通用编辑器上线后**一起删**——同一件事不并存两个入口

要你拍的一句：一期就到「正文可写」为止（agent.json 仍只读、走正规入口）， 还是连结构化文件也开写（schema 校验 + name 禁改两条规则一起上）？
