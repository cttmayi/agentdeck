# 招聘官访谈（interviewer-in-chat）设计

> 状态：**设计稿，未实作**。配套决策记录：实现时补 D 号（`docs/srs/requirements.md` §16）。
> 需求来源：使用者 2026-11-09 读完《把 AI 当员工：Lauren Tan 的七条工作法》后提出
> 「先设计 招聘官访谈」。文章的七条之一（原文第 1 条）：**第一个 AI 不干活，先当
> "招聘官"**——先问清"你是谁、你要什么、边界在哪"，再生成一张**岗位卡**（目标 /
> 职责 / 工具 / 边界 / 输出格式）；岗位卡是**草稿不是合同**，尤其要审"不能做什么"
> 那一栏。
> 使用者 2026-11-09 定稿：**两步走、两步不连接**——① 访谈官智能体在**聊天页**和
> 用户找方向；② 有方向后用户**自己**按方向去生成智能体。原「问卷面板四步流水线」
> 设计（问卷 → 素材 → agent-draft 起草 run → 分节审阅 → commit）**整个放弃**。

## 1. 背景与目标

现状：新建智能体是**填表**（`NewAgentForm`：名称 / 角色 / 指令 / 挂技能 / 审核标准）。
表单把所有"组织上下文"压回使用者自己脑子里——它不问"你最烦哪些活、绝不许它碰什么"，
于是建出来的智能体只有两种下场：指令太泛（万能助手）、或边界没说（什么都接）。

文章给的解法是**反过来的**：先访谈、后建卡。招聘官的价值不在"生成"，在**挖掘**——
"每天最烦哪些活"这类问题逼使用者说出高频、低价值、可交接的任务，那才是适合自动化的
岗位。岗位卡的五个字段不是给模型的 prompt，是**给人看、可审、可改**的草稿。

**目标（两段式，使用者定稿）**：

```
① 聊天页找方向          ② 按方向生成智能体（用户自己操作）
   用户 ↔ 访谈官（内置）     用户把「岗位卡方向」总结
   自适应追问，挖五字段      抄进新建智能体表单
        │                     ▲
        └── 不连接 ────────────┘
```

两步**没有操作连接**：访谈只负责把"你是谁、你要什么、边界在哪"从脑子里挖出来；
建智能体是用户手动的下一件事。将来 §4.1.3「沉淀 Agent」可以把这条对话直接变成
智能体指令——那是自动化的版本，v1 不做（§6）。

## 2. 为什么放弃「问卷面板」方案（2026-11 使用者定稿）

上一版设计是智能体页的「访谈生成」面板：固定问卷六问 → 答案落素材 → 一次
`agent-draft` 起草 run 产岗位卡 → 分节审阅 → commit 建智能体。使用者拍板放弃：

1. **绕**：找方向这件事本来是"坐下来问几句"，被做成了四步流水线，还要一次起草
   run、一张审阅表单——把简单的事变重了。
2. **追问才是招聘官的价值**：固定问卷把"追问"砍掉了（v1 曾以"审阅即追问"搪塞），
   而文章的招聘官恰恰靠追问挖边界。放在聊天页，追问是**天然的**。
3. **两步本来就该独立**：访谈是访谈（聊天），建智能体是建智能体（动手）。中间的
   素材 / 起草 / 审阅 / commit 是为"自动连接"付的成本，而使用者明确不要连接。

**因此本版不做**：问卷表单、`material/` 素材目录、`agent-draft` subject、岗位卡
分节审阅、commit 链、`card-drafter` 内置智能体、独立接口族——全部删掉。

## 3. ① 访谈官（内置智能体，聊天页找方向）

### 3.1 是什么

平台内置智能体「访谈官（内置）」，角色 `interviewer`。在聊天页**可以直接选它开对话**
（和普通执行者一样出现在「新对话」下拉里），然后像聊天一样回答它的问题。

### 3.2 角色放行（两处小改，都有测试钉住）

聊天目前只接受 `role === 'executor'`（daemon 门 `POST /api/conversations` 的
`agent_role_mismatch` + web 选择器 `executorChoices`）。访谈官要能进聊天，放行两处：

| 位置 | 改动 | 钉住 |
|---|---|---|
| `apps/daemon/src/server.ts` conversations POST | 角色判据从 `!== 'executor'` 改为 `!== 'executor' && !== 'interviewer'`，WHY 注释说明"访谈官只访谈不干活，聊天的产出是方向不是判决" | 现有 `chat.test.ts` 加一条 |
| `apps/web/src/lib/chat.ts` `executorChoices` | 同款放行 | `chat.test.ts` 对应判据 |

⚠️ 为什么要新角色而不是直接给 `role: 'executor'`：仓库纪律是**内置智能体绝不进业务
选择**（各处判据是 `role === 'executor'` / `'reviewer'` 等值判断）。给访谈官
`executor` 会让它能被选进智能体组去干业务活——它的指令是"只问不干"，派去干活就是
静默坏掉。新角色 `interviewer` 天然被等值判断排除（业务选择、组、任务都不认它），
只有**聊天**这一处显式放行。

### 3.3 内置纪律（与 `memory-tidy` 同一套）

- 启动对账建出来（`ensureBuiltinInterviewer`），幂等 / 自愈 / 不许删；
- 「智能体」页可见、可编辑、可「恢复成默认值」；
- 默认指令的历史版本**逐字冻结**（升级判据 = 存着的 === 已知历史），防"规矩改了
  却没到老工作区"（第 248/249 批的教训）；
- 通用工作守则（`withConduct` / `agent-conduct.ts`）与其他内置共用，不留第二份。

### 3.4 指令要点（只问不干）

身份（`withConduct` 包裹）里写死的规矩：

1. **你是访谈官：帮人把"一个岗位"说清楚，不干活**。用户派活 / 求产出时，引导回
   到岗位本身，不做任务。
2. **按岗位卡五字段追问**：目标（做什么，一句话 + 2–3 件事）→ 职责（最常被叫去
   干的活，"每天最烦的活"）→ 输出格式（长什么样，给例子）→ **边界（绝不能碰
   什么——必问，追问到用户说清为止）** → 背景（黑话 / 历史决策 / 审美偏好）。
   允许用户说"没有"，但**"没有边界"也要明说**，不许跳过。
3. **边界为空时给最小权限缺省段**，写进方向总结（与平台"判过才动、不可逆操作前
   停"同口径）：
   - 不主动触发任何不可逆操作（删除、覆盖、对外发送、修改他人文件）。
   - 拿不准的事先停下、说明、等确认，不猜着执行。
   - 只在本次工作目录里动手。
4. **问完输出「岗位卡方向」**（§4 的格式）——这是它唯一的"产出"，也是第二步的
   输入。用户没说要结束时**不主动结束**；方向总结在用户表示聊够了之后给出。
5. 岗位卡是草稿：方向总结里明确"这里是草稿，建智能体之前尤其要审『边界』那一栏"。

### 3.5 不用技能、不用记忆

访谈官不挂技能（它的"手段"就是提问）；记忆功能默认关（它不积累偏好，每次访谈
都该从一张白纸开始——上一场访谈的结论不该污染下一场）。

## 4. 「岗位卡方向」总结格式（第二步的输入）

访谈结尾输出一段固定结构，用户**复制**进新建智能体表单（§5 映射）：

```markdown
## 岗位卡方向（草稿）
- 岗位名称：会议纪要助理
- 角色：executor              # executor | reviewer
- 目标/职责：把妙记链接变成一页会议纪要；转写 → 提炼 → 分节 → 交付；缺信息先停下
- 边界（不能碰，必审）：
  - 不替参会人做决定（decisions 只列不判）
  - 不对外发送；只在工作目录里写文件
  - 缺关键信息时不猜，先问
- 输出格式：decisions / owners / deadlines 三段，每段一行一个；来源链接附末尾
- 验收标准：decisions 逐条有 owner + deadline；无主条目不许出现
- 建议挂载技能：meeting-notes（已有）
```

这段是**对话的产出**，不是两步骤的连接——用户自己复制、自己粘贴。访谈官不知道
也不关心用户第二步怎么用。

## 5. ② 按方向生成智能体（用户自己操作，无连接）

用户把 §4 的方向总结带进**现有**「新建智能体」表单（`NewAgentForm`，零改动）：

| 方向总结 | 表单字段 |
|---|---|
| 岗位名称 | 名称 |
| 角色 | 角色（executor / reviewer） |
| 目标/职责 + 边界 + 输出格式 | 指令（一段粘贴） |
| 验收标准 | 审核标准（role = reviewer 时）；执行者的验收走智能体组 |
| 建议挂载技能 | 技能勾选（从技能库选挂，"安装 SKILL"= 这一栏） |

动作权限照旧不落智能体（属于组）——与现状一致，访谈不影响这条口径。

## 6. 与「沉淀 Agent」（§4.1.3）的关系：将来的自动化连接

使用者明确"两步不需要操作连接"。将来若想省掉"复制粘贴"这一步，**沉淀 Agent**
（`skill-crystallization.md` §4.1.3，反向沉淀：对话/任务经验 → 更新 `Agent.instructions`）
正是这条对话的自动化版本——访谈对话就是它的素材。v1 不做、不预留接口（做的时候
按 §4.1.3 的复用口子走）。**别现在就把连接焊上**：用户自己操作是使用者拍板的行为，
不是待优化的缺口。

## 7. 界面改动

极小，两处：
- 聊天页「新对话」下拉出现「访谈官（内置）」选项（§3.2 的 `executorChoices` 放行
  后自然出现）；
- 智能体页列表出现「访谈官（内置）」一条（可查看 / 编辑 / 恢复默认，同
  memory-tidy）。

无新面板、无新页面、无新端点。

## 8. 测试策略

- **单测 / e2e**（假 AgentBackend，不烧真实 CLI）：
  - `POST /api/conversations` 接受 `interviewer` 角色（daemon 门放行），仍拒绝
    `reviewer` / `drafter` / `memory-tidy`（现有判据不回归）；
  - `executorChoices` 包含 `interviewer`（web 选择器，`chat.test.ts` 钉住）；
  - 内置对账（与 memory-tidy 同规矩）：启动建出来、可恢复默认、历史版本冻结、
    **不被选去干业务活**（不进组、不进任务选择器，等值判断天然排除——补进
    `agents-create` 判据）。
- **探针**（`probe:layout`）：聊天页「新对话」下拉里有「访谈官」选项；智能体页
  列表里有「访谈官（内置）」。

## 9. 边界与风险

1. **token 成本**：每次访谈 = 一次普通聊天对话，与平时聊天同量级；没有额外的
   起草 run。
2. **岗位卡是草稿，不是合同**：访谈官在方向总结里明说"建之前要审边界栏"；
   平台不替用户确认（建智能体仍是现有表单的保存动作）。
3. **内置角色纪律**：`interviewer` 必须满足"不进业务选择"（等值判断天然排除），
   聊天放行只改那两处、各带 WHY 注释，防"顺手把别的内置也放进聊天"。
4. **不提前焊连接**：§6 明确"用户自己操作"是拍板行为；将来做沉淀 Agent 时按
   §4.1.3 复用口子走，不在本设计里留半套接口。
