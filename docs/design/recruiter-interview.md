# 生成智能体（工作目录 agent/ 驱动）+ 访谈官 设计

> 状态：**设计稿，未实作**。配套决策记录：实现时补 D 号（`docs/srs/requirements.md` §16）。
> 需求来源：使用者 2026-11-09 读完《把 AI 当员工：Lauren Tan 的七条工作法》后提出
> 「先设计 招聘官访谈」。文章的七条之一（原文第 1 条）：**第一个 AI 不干活，先当
> "招聘官"**——先问清"你是谁、你要什么、边界在哪"，再生成一张**岗位卡**（目标 /
> 职责 / 工具 / 边界 / 输出格式）；岗位卡是**草稿不是合同**，尤其要审"不能做什么"
> 那一栏。
> 使用者六轮定稿（2026-11-09）：
> ① 两步走、两步无连接；
> ② 第 2 步必须有 AI 起草（"还会通过智能体动态生成智能体吗——我的理解要"）；
> ③ 第 2 步与第 1 步解耦、栏位最少、用户可以直接做第 2 步；
> ④ 功能独立（"不应该复用现有表单"）；
> ⑤ 产出仍是智能体，**技能不是外挂勾选、是 AI 起草的**（"智能体内可包括
>    SKILL，不是外挂的，是 AI 自己起草的"）；
> ⑥ **全部改到聊天页**："聊天页多一个功能，自动侦测工作目录下的 `agent` 目录，
>    如果存在此目录，就多一个按钮，可以根据 agent 目录下的资讯生成智能体"——
>    独立面板、要求输入框、产出类型选择全部删除，换成"工作目录 `agent/` →
>    按钮 → 从目录资讯生成智能体（含配套技能）"。

## 1. 背景与目标

现状：新建智能体是**填表**。使用者六轮后定下的形态：**一切发生在聊天页**——在
对话的工作目录里放一个 `agent/` 目录（要求、资料、示例、边界规范……想放什么放
什么），聊天页**自动侦测**到它，就多一个「生成智能体」按钮；点它，AI 从目录里的
资讯起草智能体（含 AI 起草的配套技能），审阅后确认创建。

**为什么这样最好**（与「沉淀技能」同构，使用者熟、且贴工作现场）：

```
工作目录                         聊天页                          结果
conversation-<id>/          [ 沉淀技能 ] [ 生成智能体 ]        agent-draft run
  agent/  ←─自动侦测────→   按钮出现(有 agent/)   ──→  card-drafter 起草智能体
    （资讯：要求/资料/         点它 ──→              + 配套技能清单
      示例/边界规范…）         审阅 → 确认            → skill-draft runs(沉淀起草者)
                                                    → 创建智能体 + 技能沉淀
```

- **素材的自然位置就是工作目录**：想生成智能体的人，把素材放进 `agent/` 就行，
  不用往面板里粘文本；
- **侦测即入口**：目录在，按钮在；没有 `agent/` 就不出现（与"沉淀技能"按钮
  同一种"按条件出现"的模式）；
- **访谈官仍是可选的聊天智能体**（功能 B，不变）：想先理清方向就聊，聊出的
  方向可以写进 `agent/` 目录再点按钮——A、B 依旧不连接。

## 2. 为什么放弃「独立面板 + 要求输入框」（2026-11 使用者第六轮定稿）

前五轮把功能 A 做成"智能体页独立面板：写一段要求 → AI 起草"。使用者拍板放弃：

1. **要求框是多余的输入**：素材放进工作目录 `agent/` 就是"要求"，往面板再粘一遍
   是重复劳动；而且目录能装下要求框装不下的东西（示例文件、规范文档、参考资料）。
2. **生成发生在工作现场**：聊天页是使用者干活的地方，工作目录就在眼前——按钮
   出现在这里，比"切到智能体页找独立面板"顺。
3. **与沉淀同构**：沉淀就是"对话/run → 按钮 → 起草 → 审阅 → 确认"，生成智能体
   应该长同一个样子，而不是再造一个面板族。

**因此删除**：独立面板、要求输入框、产出类型选择、`/api/requirements/*` 接口族。
**保留**：产出 = 智能体 + AI 起草的配套技能（第 ⑤ 轮拍板）、两个内置起草者、
 边界缺省纪律、共享技能定性。

## 3. 功能 A：生成智能体（聊天页，agent/ 目录驱动）

### 3.1 侦测：工作目录下的 `agent/` 目录 → 按钮

- 每个对话有自己的工作目录（`conversation-<id>/`，聊天页文件树就是它）。
- 侦测规则：工作目录**顶层**存在 `agent/` 目录 → 聊天页对话栏头（「沉淀技能」
  按钮旁）出现「**生成智能体**」按钮；不存在就不出现。
- 侦测用现成的文件树数据（对话详情已返回工作目录文件清单），不新增轮询。

### 3.2 生成流程（点「生成智能体」）

1. **素材收集**：`agent/` 目录**全部内容**（递归）收集为素材（§3.3）。
2. **agent-draft run**（subject `agent-draft`，`entities.ts` 枚举加值，§4.1.3 已
   预留；执行者 = 内置「岗位卡起草者」`card-drafter`）→ 产出 `agent-draft.md`：
   frontmatter（name/role）+ 正文一段指令（**必须有边界段**，素材里没提边界时写
   最小权限缺省段），末尾一节「**配套技能**」清单（0..N 条：slug / name / 一句
   描述——它认为素材里哪些做法值得抽成技能；认为没有就 0 条）。
3. **按清单逐个发起 skill-draft run**（subject `skill-draft`，**现有**机制；执行者
   = **现有沉淀起草者**，挂 distilly，技能写作规范正好对口）→ 每条产出
   `SKILL.md`。素材 = 收集的素材 + agent-draft.md 里那条配套技能的说明（沉淀素材
   源从 run 扩展到 `agent/` 目录，§5）。
4. **审阅**：聊天页内联面板（§3.5）。
5. **确认**（§3.6）：先沉淀配套技能，再创建智能体。

配套技能数量由起草者按素材判断（0..N），用户审阅时可删可改可加。

### 3.3 素材（一条纪律：起草者唯一依据 = agent/ 目录内容）

```
conversation-<id>/
  agent/                        ← 使用者的素材（想放什么放什么）
    （要求.md / 资料 / 示例 / 边界规范……任意文件）
    ↓ 收集
agent-generation-<id>/material/
  meta.json     ← 来源（agent 目录）、创建时间
  00-素材.md    ← agent/ 目录内容的汇总（含各文件原文）
```

起草者只读 material/，不许编。素材没说清的部分，草稿相应处标「待补：xxx」并写清
缺什么——与沉淀"不结晶清单"同一纪律。

### 3.4 起草者（与第五轮相同）

- 智能体：内置「岗位卡起草者」`card-drafter`。为什么不用沉淀的起草者：① 其身份
  在第 191 批**有意**收窄成"只干一件事"（写 skill），写智能体 = 身份与任务书打架
  （第 51 批教训）；② 其挂 `distilly`（SKILL 写作规范），对智能体草稿是错误注入，
  而注入不能按 subject 分叉（第二份真相）；③ 仓库内置模式 = "一个岗位一条内置 +
  专属 role + 不进业务选择"（memory-tidy 先例）。
- 配套技能：**现有沉淀起草者**（skill-draft run，身份对口，不用新开）。
- 两个内置各司其职，不互相越界。

### 3.5 审阅（聊天页内联面板）

点「生成智能体」后，聊天页出现生成面板（内联展开，不是新页面）：

- **RunLog 常驻**：agent-draft run + 各 skill-draft run 的日志流（与沉淀页同组件）。
- **智能体部分**：名称 / 角色 / 指令（一段，边界在段内，下方提示「草稿不是合同——
  检查『边界』段」，提示不是校验）。
- **配套技能部分**：每条技能一块（slug / name / description / body，复用沉淀草稿
  审阅骨架），每条顶部提示：「此技能草稿来自素材，**未经验证**——建议先让智能体
  干几轮，再用沉淀结晶正式版」（提示不是校验）。可删可改。
- 切走页面再回来还在（恢复进行中，与沉淀同机制）。

### 3.6 确认生成（人确认是唯一入口）

- 每条配套技能走**沉淀 commit** → 落 `skills-mine` + git（共享，可被其他智能体
  挂载）。
- 再 `POST /api/agents`：name/role/instructions，`skillIds` = 配套新技能 + 用户
  另勾的已有技能。顺序：先沉淀技能、再建智能体（skillIds 要指向已存在的技能）。
- 动作权限不落智能体（属于组）。

### 3.7 技能是共享资产，不是私有（平台定性，v1 不变）

配套技能落库后和所有技能一样：磁盘 `skillsRoot`、mine 进 `skills-mine` git、
任何智能体都能挂。**不做"仅此智能体可用"的私有技能**：技能是共享资产是平台定性
（文章第 4 条也是"存成 SKILL 进 Git"共享），私有化是新面（新存储 + 新的注入通道
+ git 处理），v1 不为配套技能付出整个私有面。要私有技能，另起设计再议。

## 4. 功能 B：访谈官（可选，独立，聊天页找方向）

### 4.1 是什么

平台内置智能体「访谈官（内置）」，角色 `interviewer`。聊天页「新对话」下拉可直接
选它开对话。**独立功能**：聊出的「岗位卡方向」只是参考——想用就把方向写进
`agent/` 目录（或直接当素材），再点「生成智能体」；不想就自己写。没有自动传递、
没有连接。

### 4.2 角色放行（两处小改，都有测试钉住）

聊天目前只接受 `role === 'executor'`。放行 `interviewer` 两处：

| 位置 | 改动 | 钉住 |
|---|---|---|
| `apps/daemon/src/server.ts` conversations POST | 角色判据放行 `interviewer`，WHY 注释："访谈官只访谈不干活，聊天的产出是方向不是判决" | `chat.test.ts` 加一条 |
| `apps/web/src/lib/chat.ts` `executorChoices` | 同款放行 | `chat.test.ts` 对应判据 |

新角色天然被业务选择的等值判断排除（不进组、不进任务），只有聊天这一处放行。

### 4.3 内置纪律（与 memory-tidy 同一套）

启动对账建出来、幂等/自愈/不许删、智能体页可见可编辑可恢复默认、历史版本逐字
冻结升级（第 248/249 批教训）、通用守则（`withConduct`）共用。

### 4.4 指令要点（只问不干）

1. 你是访谈官：帮人把"一个岗位"说清楚，**不干活**；用户派活引导回岗位本身。
2. 按岗位卡五字段追问：目标 → 职责（"每天最烦的活"）→ 输出格式（给例子）→
   **边界（必问，追问到说清为止，"没有"也要明说）** → 背景。
3. 边界为空时给最小权限缺省段，写进方向总结。
4. 问完输出「岗位卡方向」总结（§4.5）——用户表示聊够了之后才给，不主动结束。
5. 方向总结注明"草稿——建之前尤其要审『边界』"。

不用技能、记忆默认关（上一场访谈不污染下一场）。

### 4.5 「岗位卡方向」总结（给用户看的参考）

```markdown
## 岗位卡方向（草稿）
- 岗位名称：会议纪要助理
- 角色：executor
- 目标/职责：…… / 边界（不能碰，必审）：…… / 输出格式：……
- 验收标准：……
- 建议挂载技能：meeting-notes（已有）
```

用户可把这段写进 `agent/` 目录当素材，或直接抄进目录里的要求文件——功能 A 只认
`agent/` 目录里的内容。

## 5. 与「沉淀」和「沉淀 Agent」（§4.1.3）的关系

- **配套技能 = 沉淀的"素材源扩展"**：沉淀现在从真实 run 收集素材；生成智能体把
  素材源扩成"工作目录 `agent/`"，起草/审阅/commit 全部复用 skill-draft 骨架，
  **不复制逻辑**。代价是技能未经验证（§1/§3.5 明说，审阅时提示）。
- **智能体 = §4.1.3「沉淀 Agent」的简化落地**：素材源是 `agent/` 目录而不是对话，
  产出是新建智能体；将来沉淀页把「沉淀技能 / 沉淀智能体」并排时（§4.1.3），
  agent-draft + card-drafter 直接复用。
- **「生成智能体」与「沉淀技能」按钮同构并存**：一个从工作目录 `agent/` 生成
  智能体，一个从对话/run 沉淀技能，互不干扰。

## 6. 界面改动（全部在聊天页 + 智能体列表）

- 聊天页：对话栏头（「沉淀技能」旁）加「**生成智能体**」按钮——工作目录顶层有
  `agent/` 才出现；点了内联展开生成面板（RunLog + 草稿审阅，§3.5）。
- 聊天页：「新对话」下拉出现「访谈官（内置）」。
- 智能体页列表：出现「访谈官（内置）」与「岗位卡起草者（内置）」两条（可查看 /
  编辑 / 恢复默认，同 memory-tidy）。

## 7. 测试策略

- **单测 / e2e**（假 AgentBackend，不烧真实 CLI）：
  - `POST /api/conversations` 接受 `interviewer`，仍拒绝 `reviewer`/`drafter`/
    `memory-tidy`（不回归）；`executorChoices` 包含 `interviewer`（`chat.test.ts` 钉住）；
  - **侦测**：对话工作目录顶层有 `agent/` → 详情返回可生成标记（无则无）；无
    `agent/` 不出现按钮；
  - **整链**：`agent/` 目录内容 → 素材收集（汇总落盘）→ agent-draft run（fake
    card-drafter 产 agent-draft.md，含配套技能清单）→ 配套技能 skill-draft runs
    （fake 沉淀起草者产 SKILL.md）→ 审阅（改边界、删一条技能）→ 确认 → 断言
    `GET /api/agents` 新智能体 skillIds = 已沉淀技能、技能落 `skills-mine` + git；
  - **配套技能为 0 条**时只建智能体（无技能 run）；
  - **素材没提边界时**智能体草稿含最小权限缺省段；
  - **独立性**：不用访谈也能生成（无前置依赖）；访谈对话不会自动触发生成；
  - 内置对账（两条新内置）：启动建出来、可恢复默认、历史版本冻结、不进业务选择
    （补进 `agents-create` 判据）。
- **探针**（`probe:layout`）：工作目录有 `agent/` 时聊天页出现「生成智能体」按钮
  （无则没有）；生成面板（RunLog + 两段审阅区）；聊天下拉有「访谈官」。

## 8. 协议草案（对话内嵌，实现时定细节）

| 端点 | 说明 |
|---|---|
| `GET /api/conversations/:id` | 详情里带 `hasAgentDir`（工作目录顶层有 `agent/`）——侦测 |
| `POST /api/conversations/:id/agent-generations` | 收集 `agent/` 素材 + 发起 agent-draft run，返回 runId |
| `GET /api/agent-generations/:id` | 素材 + 各 run 状态 + 智能体草稿 + 配套技能草稿 + RunLog |
| `PATCH /api/agent-generations/:id/draft` | 审阅修改（草稿修订） |
| `POST /api/agent-generations/:id/commit` `{finalDraft, skillIds}` | 人确认：先沉淀配套技能（复用沉淀 commit），再 `POST /api/agents` |

创建动作仍走现有端点（智能体 `POST /api/agents`、技能沉淀 commit），新接口只负责
"素材 → 草稿 → 审阅 → 确认"这一段，不复制创建逻辑。

## 9. 边界与风险

1. **配套技能未经验证（拍板取舍）**：AI 从素材起草的技能草稿没有真实 run 背书。
   审阅时明示"未经验证"（提示不是校验）；要正式版走沉淀。写进这里防将来有人
   忘了为什么。
2. **配套技能数量由 AI 判断**：0..N 条；用户可删可改可加。素材没有可复用做法时
   0 条是合法的。
3. **token 成本**：一次生成 = 一次 agent-draft run + 按需的 skill-draft runs；访谈
   另算（可选）。与沉淀同量级。
4. **草稿不是合同**：AI 只起草，确认（commit）是唯一入口；"检查边界段 / 未经验证"
   是提示不是校验。
5. **内置角色纪律**：`interviewer` / `card-drafter` 不进业务选择（等值判断天然
   排除）；聊天放行只改 `interviewer` 那两处、各带 WHY 注释；配套技能 run 用现有
   沉淀起草者，不新开。
6. **技能是共享资产**：配套技能落库后任何智能体可挂；私有技能概念 v1 不做（§3.7）。
7. **「生成智能体」按钮按条件出现**：工作目录顶层没有 `agent/` 就不出现——与
   「沉淀技能」按钮同一模式，不搞"置灰"（没有素材时置灰按钮是一种半开的门）。
8. **A、B 独立是拍板行为**：访谈官聊出的方向只是参考，不自动进 `agent/`、不自动
   触发生成。
