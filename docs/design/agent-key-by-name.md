# 把 Agent 的键从 ULID 改成名字（slug）——迁移清单

> 使用者 2026-11 拍板：**选 C**（`agents/<name>/`，名字即键）。
> 本文是**动手之前**的清单：改哪些、按什么顺序改、哪些是无法回避的代价、哪几件事需要使用者先定。
> 现状（id 为键）见 [`storage-layout.md`](./storage-layout.md) §3。

---

## 0. 一句话结论

**能做，但它不是"把 id 换成 name"这一处改动**——它把「改名」从"改一个字段"变成"一次跨全库的
迁移"，并且会让**历史记录**（run / issue / conversation / memory）里那个键在改名后不再对应任何
智能体。后者只有两个出路：**加别名（推荐）**或**接受断链**。

---

## 2. slug 规则（先定死，再动手）

名字是自由文本，直接当目录名会踩四类坑。规则建议如下（**都用真名跑过一遍，现有 11 个不冲突**）：

1. **保留中日韩字符**（`智能体生成者` → `智能体生成者`，不改写、不拼音化）：本机工具，人能认最重要。
2. **ASCII 一律转小写**（`Writer` → `writer`）：避免 macOS 大小写不敏感导致"两个目录其实是同一个"。
3. **非法字符 → `-`**：`/ \ : * ? " < > |`、控制字符、以及空白（空白折成 `-`）。
4. **压掉连续 `-`、去掉首尾 `-`**；空结果 ⇒ 用 `agent-<序号>` 并提示使用者改名。
5. **长度上限 60**（UTF-16 码元），超了截断后若有碰撞再追加 `-2`。
6. **保留名**：`.` 与 `..`、以 `.` 开头、Windows 设备名（`CON` `PRN` `AUX` `NUL` `COM1..9` `LPT1..9`）
   —— 这几类一律加前缀 `agent-`（Windows 上这些名字建不出目录，`platform-compat.md` 有同类纪律）。
7. **唯一性判据 = slug 逐字相等（已转小写）**，比现在 `duplicateNameOf` 的"名字逐字相等"更严
   —— 这是当键的必然代价：`Writer` 与 `writer` 今后算撞名（现在算两个）。

## 3. 三个必须先定的决定（我给了建议）

### 决定 1：跨工作区同名怎么办 ⚠️ **硬冲突**

- 现状：`duplicateNameOf(store, workspaceId, …)` 只在**同一个工作区**内查重；
  而 `agents/` 目录是**全局平铺**的（`agentsRoot(dataDir)`，跨工作区共用）。
- 于是两个工作区各有一个「写作员」是完全合法的 → 同一个 slug → **目录撞车**。
- 三条出路：
  - **(a) 名字改成全局唯一**（推荐）：查重不再带 `workspaceId`。代价是"两个工作区不能各有一个写作员"；
    好处是目录名干净、`agents/` 的语义从"全局平铺 + 按 workspaceId 过滤"变成"全局唯一"。
  - (b) 目录带工作区前缀：`agents/<wsShort>--<slug>/` —— 丑，但不动语义。**不推荐**（本来就是为了让目录好认）。
  - (c) 把 `agents/` 改成按工作区分目录（`workspaces/<ws>/agents/<slug>/`）—— 大迁移，与本议题无关的连带改动。
- **你需要说 (a) 还是 (b)。今天你只有一个工作区，所以这条现在不做也不会炸，但规则必须先定。**

### 决定 2：历史断链怎么处理 ⚠️ **这次迁移的代价所在**

改名后，老 `Run.agentRef.id` / `Issue.assignee.id` 里的旧 slug 不再对应任何智能体。

- **(a) 加 `Agent.aliases: string[]`**（推荐）：改名时把旧 slug 记进去（保留最近 20 个）。
  **历史不被改写**（DR-3 仍然成立），但"点开那条老 run 的执行者"仍然找得到人——
  解析时先按 `id` 找，找不到再按 `aliases` 找，命中时界面标「（旧名）」。
- (b) 接受断链：老记录只显示 `agentRef.name` 快照（本来就存了），"跳转到智能体"按钮失效。
- ⚠️ **不能选的做法**：改写历史日志（append-only + DR-3 明令禁止，而且同样要在全库范围写 patch）。

### 决定 3：`AgentId` 这个类型名要不要跟着改

- **(a) 保留 `AgentId`，只改值域与校验**（推荐）：类型改动小，历史数据的类型不变；
  语义上"id 现在就是 slug"写在注释里。
- (b) 引入 `AgentKey` / 把 `AgentId` 标记为过时：语义更准，但要动 12 处签名与前端类型。

## 4. 迁移步骤（一次性、幂等、可停可续、ledger 记名）

顺序是硬的：**先把引用算清楚，再改数据，最后改目录**——中断在任何一步，都能靠"再跑一次"补齐。

1. **体检（只读，不改任何东西）**
   - 扫 `agents/*/agent.json`：算 slug；检查 (i) slug 冲突、(ii) 跨工作区同名、(iii) 非法/保留名、
     (iv) 大小写打架（`Writer` vs `writer`）。
   - 有任何一条不可自动解决 ⇒ **停下**，把清单打出来让使用者改名后再跑（不猜）。
2. **改记录**（每条独立、可重入）：
   1. `agent.json`：`id` = slug，`aliases` 追加旧 id（决定 2 选 a 时）；
   2. `workspaces.json`：`defaultAgentId`、`platformSlots` 的每个值；
   3. 各工作区 `log/` 里 `conversation` / `chat-turn` / `run` / `issue` / `memory` 记录里的 agent 引用
      （追加一条 patch，**不删历史**）；
   4. `schedules.json`（或 `<dataDir>/schedules/<id>/schedule.json`）的 `executorId`。
3. **改目录**：`agents/<oldId>/` → `agents/<slug>/`；`memory/<oldId>/` → `memory/<slug>/`
   （两步 rename，与 D229 同一个理由：大小写不敏感的文件系统）。
4. **记账**：`migrations.json` 记 `agent-key-by-name: {v:1}`；同时写一份
   `agents/.id-map-<时间戳>.json`（旧 id ↔ slug），**留到使用者确认无误后再删**（一次性键替换，
   回滚只能靠它）。
5. **对账**：跑一遍"每个引用都能解析成存在的智能体"，把悬空的点名（§7 的判据）。

**为什么不能"就改个字段"**：`Run` / `Issue` 这些是 append-only 日志 + 内存索引；
改历史记录的键只能靠**追加 patch**（合法），而"改名后老 run 指向旧 slug"这件事
**只有别名能救**（决定 2）。

---

## 5. 改名（日常操作，不是迁移）从此变成这样

今天：改名 = `agent.json` 写一个 `name` 字段（1 次原子写）。

改成 C 之后，改名 = **事务性迁移**：

1. `slugify(newName)`；冲突检查（含大小写与保留名）；
2. 新 slug 写进 `agent.json.id`，旧 slug 进 `aliases`；
3. 改上面 §1 那 8 处引用（append patch 或 upsert）；
4. `rename` 两个目录（`agents/`、`memory/`）；
5. 任何一步失败 ⇒ 回滚到旧 slug（因为旧 slug 还在 aliases 里，回滚是"再走一遍"，不是猜）。

⚠️ 这条是 C 相对 B 的**主要成本**：改名从"零风险的一字段写"变成"跨库事务"。
建议同时做两件事兜底：**改名只允许一次一个**（加锁，不许并发）、**失败要在界面上说出来**（不能静默留在半路）。

---

## 6. 平台内置成员的额外注意

- 认人靠 `platformSlots`（槽位 → 键）与 `builtinKind`，**不靠名字**。键变成 slug 之后，
  槽位里存的是 slug；内置被改名 ⇒ 槽位值要一起改（§5 第 3 步），否则自愈会认为"还没有那一条"
  并**新建一条**（那就变成两条内置了）。
- `builtinDefaultsOf()` 的"恢复默认值"会**改名字** ⇒ 按 §5 走完整改名流程，不能只改字段。

---

## 7. 判据（跟着迁移一起加）

1. **slug 规则**：非法字符/大小写/保留名/长度/空名的表驱动用例；
2. **唯一性**：`Writer` 与 `writer` 算撞名（与今天不同，要写成判据防止回退）；
3. **迁移体检**：造一个"跨工作区同名"的库 ⇒ 迁移**拒绝执行**并点名（不猜）；
4. **迁移可重入**：跑一半中断再跑 ⇒ 结果一致（引用全部解析成功）；
5. **别名**：改名后按旧 slug 能查到人，界面标「（旧名）」，且 `agents/` 里**没有**旧目录；
6. **改名事务**：改名失败时引用与目录都回到旧 slug（不留下半路状态）；
7. **对账**：全库每个 agent 引用（§1 那 8 处）都能解析成存在的 slug。

---

## 8. 工作量与风险评级

| 项 | 量级 | 风险 |
|---|---|---|
| slug 规则 + 校验 + 唯一性收紧 | 小 | 低（纯函数 + 判据） |
| 生成点改 slug（10 处） | 小 | 低 |
| 迁移脚本（体检 / 改引用 / 改目录 / 记账 / 对账） | 中 | **高**（一次性改写全库引用） |
| 改名改成事务（加锁、回滚、界面反馈） | 中 | 中高（日常路径，失败要可见） |
| 别名解析 + 界面「（旧名）」 | 中 | 中（涉及 run/issue 详情页） |
| 判据与文档 | 中 | 低 |

**最大风险不是写不出来，而是"改到一半"**：所以迁移必须①先体检后动手、②每步幂等可重入、
③保留 `.id-map-*.json` 直到确认、④改名路径加锁并让失败可见。

## 9. 需要你现在拍板的三件事

1. **同名跨工作区**：(a) 全局唯一（推荐）还是 (b) 目录带工作区前缀？
2. **历史断链**：(a) 加 `Agent.aliases`（推荐，历史仍可追）还是 (b) 接受断链？
3. **`AgentId` 类型名**：(a) 保留、只改值（推荐）还是 (b) 改名 `AgentKey`？
