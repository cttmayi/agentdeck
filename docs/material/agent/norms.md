# 岗位卡怎么写（指令的那一段）

智能体的全部规则都在 `instructions.md` **一段**里。按下面的顺序写，人审的时候一眼看得完。

## 1. 五字段（缺一不可）

| 字段 | 写什么 | 反例 |
|---|---|---|
| **目标** | 一句话：这个岗位做什么 | "帮忙处理文档"（太空） |
| **职责** | 最常被叫去干的 2–3 件事，动词开头 | 列出 15 件事（读不完） |
| **边界（不能碰）** | 逐条禁止事项，**必含** | 留空 / 写"没有边界" |
| **输出格式** | 产出长什么样，有例子给例子 | "输出要清晰" |
| **验收标准** | 怎么算干好了：可检查、可勾选 | "符合要求" |

## 2. 一段组装，顺序固定

```
你是<岗位名>。

## 目标
…

## 职责
- …

## 边界（不能碰）
- …

## 输出格式
…

## 验收标准
- …
```

边界节放在**目标/职责之后、输出格式之前**——审阅时人先看到它。

## 3. 边界清单（逐条过一遍）

1. **不可逆操作**：删除、覆盖、改写他人文件、对外发送（发消息 / 发邮件 / 推送）——要么明令禁止，要么写明"先停下来问"；
2. **拿不准先停下**：缺关键信息时不猜不编，先问——写成一条明确规则；
3. **只在工作目录动手**：产出落进自己的工作目录，目录外的读写一律禁止；
4. **"没有"也要明说**：用户说"没有边界 / 你看着办"时，写最小权限缺省段，并注明"这是缺省的最小权限"；
5. **决定权归人**：判对错、定优先级、替人承诺这类事默认不碰；只列不判。

## 4. 验收标准要可检查

"输出要符合要求"是空话；"待办每条都带负责人与期限"才算一条标准。
写不出可检查的标准时，就写行为标准："缺关键信息时停下并列出缺什么"。

## 5. 配套技能：值得才写（可以 0 条）

逐条问三个问题，**三个都"是"**才抽成技能：

1. **高频吗**：每次干活都会遇到，还是这次碰巧需要？
2. **同格式吗**：产出有固定形状（格式约定、模版、固定步骤）吗？
3. **跨任务可复用吗**：别的任务/别的岗位用得上吗？

任何一个"不是"就不写——**0 条是正常答案**，凑数的技能只会让将来更难维护。
技能的形状见 `shape.md`；名字必须 kebab-case。
