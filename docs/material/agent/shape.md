# 产物形状：写成存储的样子

智能体住在一个目录里（与编排的内建智能体同形，D234）：

```
agents/<名字>/
  agent.json         结构化（不含指令正文）
  instructions.md    指令（唯一的一段正文）
  skills/<技能名>/SKILL.md   它自己带的技能（可选，可多份）
```

你在聊天里产出的**候选**要写成同一个形状，只是放在工作目录下、外面套一层"候选包"：

```
<工作目录>/agent-draft/<岗位名>/
  agent.json
  instructions.md
  skills/<技能名>/SKILL.md
```

## `agent.json` 写什么

```json
{ "name": "会议纪要助理", "runtimeKey": "default" }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 岗位名，**中文可以**（`会议纪要助理` 比 `meeting-notes` 顺）。要与目录名一致 |
| `runtimeKey` | 否 | 用哪个 CLI；缺省 `"default"` = 跟随工作区默认。**不要填你不确定的值** |
| `skillIds` | ❌ 不要写 | 内建/共享技能库的引用由平台管；这一版生成出来的智能体不挂共享技能 |

`id` / `owner` / 时间戳由平台在你点「生成智能体」时补，**你不要写**。

## `instructions.md` 写什么

就是那段"你是<岗位名>。"开头的完整指令——**只有这一段**，没有第二个文件、没有第二处注入位。
写法见 `norms.md`。

## `skills/<技能名>/SKILL.md` 写什么

配套技能是**这个岗位自己的**东西（落库后在 `agents/<名字>/skills/` 下，不进共享技能池）。
格式与普通技能一致：frontmatter 两行 + 正文。

```markdown
---
name: 纪要格式
description: 会议纪要的固定形状：三段（结论 / 待办 / 未决），待办必须带人 + 期限
---

# 纪要格式

## 用法
先写结论三句以内，再列待办（每条：谁、做什么、什么时候），最后列未决问题。
```

⚠️ `name` 必须是 **kebab-case**（小写字母/数字/连字符，≤64 字符）——它与目录名、引用键是同一个东西（D236）。
中文写在 `description` 和正文里。

## 名字的唯一性

- 目录名 = 岗位名（中文直接写），平台落库时按名字生成目录；**工作区里已经有同名智能体时落库会被拒**，
  所以要改名——不要靠"再点一次"。
