# remote-ui-probe（远端管理页的界面探针）

```bash
pnpm run probe:remote          # 需要真 Chrome；不在 `check` 里（它要起一个真服务）
```

起一个**一次性远端服务**（数据目录是夹具、同步工具是假脚本、**绝不联网**），把
`probe.html` 塞进 `apps/remote/web/dist/`（同源才能量 iframe 里的东西），用无头 Chrome
跑一遍，读回 JSON，逐条断言。

## 为什么有它

daemon 界面有一条约 470 项常驻探针（`tools/layout-probe/`），而**远端管理页一开始一项都没有**。
2026-10 做界面审查（D53）时只有临时量测脚本，量出 7 处问题——其中两处**肉眼看不出来**：

| 量到的 | 后果 |
|---|---|
| 同步按钮被同一行的长说明挤成两行（54.4px，该是 35px 那一档） | 按钮看着"正常"，只是高了一点 |
| `.table-wrap` 是 `overflow: hidden` | 窗口一窄，表格右边的列**被裁掉且无法到达**（daemon 自己那张表在 860px 下裁掉 316px） |

临时脚本用完就删了 ⇒ 下次改界面又只能靠眼睛。这个目录把那套办法固化下来。

## 分工（与 daemon 那条探针一致）

- `probe.html`——**只量事实**：量到的数值写进 `<pre id="out">`，`run.mjs` 从 `--dump-dom` 里读它；
- `run.mjs`——**判据全在这里**：每一项都有名字、有实测值，失败时逐条打印并退出码 1。

分开的理由：**"量"与"判"混在一起时，改判据就得改测量页**，而改测量页会让上一次的报告失去可比性。

## 夹具（`run.mjs` 造，跑完留着供排查）

| 夹具 | 用来验什么 |
|---|---|
| 2 条"同步来的"技能（其中一条带 `excluded`） | 来源徽标「推荐清单」、**置灰的卸载按钮**（title 里要说清"改清单再同步"）、「内容不完整」提示 |
| 1 条"手动装的"技能 | 来源徽标「本地添加」、可点的「卸载」⇒ **自己画的确认框**（不是 `window.confirm`）⇒ 取消后那一行还在 |
| 一份清单配置（`recommended-skills.json`） | 页面上那行"清单：N 条，核对于 …，文件：…"是**真实数据**（不是键名、不是硬编码） |
| 4 个工具包（用仓库自己的 `catalog/tools`） | 工具页的表头/动作/按钮 |

## 已知取舍

- **不做响应式宽度**：daemon 那条探针会跑多档宽度；这条目前只量 1400px 一档
  （窄屏的"表格可滚"是用 `overflow-x` 的**计算值**钉的，与宽度无关）。
- **不点同步按钮**：那会起子进程；探针只断言按钮**长得对、在、有标签**。
  "同步本身能跑"由 `apps/remote/src/web.test.ts` 用假脚本钉（含单飞、失败透传）。
