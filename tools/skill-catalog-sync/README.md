# skill-catalog-sync（推荐技能目录同步工具）

把一份**清单**里列的 GitHub 技能抓下来，写进一个**目录**，供远端服务当"公共目录"读。
一个命令、一次运行、跑完就退出——不是服务，也不是 daemon 的一部分。

```bash
pnpm run sync-skills --help             # 记不住选项就看这个（只读，无副作用）
pnpm run sync-skills                    # 抓取并替换目录（默认写到远端服务读的那个目录）
pnpm run sync-skills --dry-run          # 逐条真抓一遍，但不写盘
pnpm run sync-skills --refresh          # 忽略"1 小时内抓过"的复用窗口，全部重新下载
pnpm run sync-skills --out <目录>        # 写到别处
pnpm run sync-skills --manifest <文件>   # 换一份清单（显式指定，不转存；默认走配置文件）
pnpm run sync-skills --github-proxy                        # 走加速器（裸写 = https://gh-proxy.com）
pnpm run sync-skills --github-proxy https://别的加速器       # 换一个
pnpm run sync-skills --github-proxy off                     # 这次直连（也能盖掉环境变量）
```

两条行为值得先知道：**第一条失败就停**（不把剩下的挨个试一遍），以及
**1 小时内抓过的不再下载**（沿用本地那份，0 次 API 调用）。

**记不住旗标就敲 `pnpm run sync-skills --help`**（或用 `-h`）：它会打出全部选项、
环境变量、退出码，以及几条"要记得的"（失败即停 / 1 小时复用 / 断点目录）。
帮助是**只读的**——不读清单、不联网、不写盘。

需要 Node ≥ 22（与仓库其余部分一致）。**不要**写 `pnpm run sync-skills -- --dry-run`：
pnpm 会把那个 `--` 原样传进来，本工具**直接拒绝**并告诉你正确写法（见下文"为什么不忍着"）。

**参数是严格的**：不认识的参数一律报错，不会被默默忽略。这一条很重要——`--dryrun`
（少一个连字符）如果被忽略，结果不是"什么都没做"，而是**真的一次同步**（目录被替换了，
而你以为只是在干跑）。所以手滑会当场被指出来：

```
$ pnpm run sync-skills --dryrun
不认识的参数：--dryrun（是不是想写 `--dry-run`？）。可用：--dry-run、--manifest <文件>、--out <目录>。
```

## 它为什么是一个独立工具

2026-10 定案（接需求文档 **D50**）：抓取与"远端服务在跑"这件事没关系。

| 谁 | 干什么 | 不干什么 |
|---|---|---|
| **本工具** | 读清单、联网抓 GitHub、校验、原子替换目录、打印花了多少次 API 调用 | 不监听端口、不读账号/登录态、不知道谁是使用者 |
| **远端服务**（`apps/remote/`） | 读那个目录、校验、`GET /api/catalog` 返回 | **不联网、不知道 GitHub、没有一行抓取代码** |

两边**只靠一个目录相连**：没有共享代码、没有共享数据目录常量、没有互相 import。
本工具可以脱离远端单独跑；远端也可以完全没有它（目录空着就是一个空目录，界面有空态）。

```
   清单 JSON ──▶ [本工具] ──▶ 目录 ──▶ [远端服务] ──▶ 页面「安装技能」的远端目录页签
   （维护者改）   （联网抓）    （唯一约定）   （只读盘）
```

好处很具体：**抓取失败不影响服务**（服务照跑，目录保持上一次的样子）、
**工具崩了不影响服务**、**服务不需要为抓取装任何东西**。

## 清单：仓库里的是**默认值**，运行时用**配置文件**

| 位置 | 是什么 |
|---|---|
| `tools/skill-catalog-sync/recommended-skills.json` | 仓库自带的**默认值**（随版本走，会被 git 覆盖） |
| `<`--out` 的父目录>/recommended-skills.json` | **配置文件**：第一次运行时由工具把默认值**转存**过去，之后就用这一份 |

默认 `--out` 是 `~/.agentdeck/remote/catalog-skills` ⇒ 配置就是
`~/.agentdeck/remote/recommended-skills.json`。**远端服务读的是同一个文件**
（页面那行"清单：N 条，核对于 …"就是它），所以工具与页面不会各说一套。

- 配置**已存在 ⇒ 绝不覆盖**（那是你的东西）；第一次运行会打印转存到哪儿、以及"以后改哪一份"；
- `--manifest <文件>`：显式指定另一份，**不转存**（给了就按给的来，缺了直接报错）；
- **转存只发生在工具里**：服务只读。所以"还没转存"是合法状态，页面会如实说。

`recommended-skills.json` 的内容长这样：

```json
{
  "schema": "agentdeck/recommended-skills@1",
  "verifiedAt": "2026-10-05",
  "items": [
    {
      "url": "https://github.com/anthropics/skills/tree/main/skills/pptx",
      "name": "PowerPoint 生成",
      "category": "文档",
      "origin": "official",
      "summary": "一句话说清它干什么。",
      "fills": "装上之后能做什么。",
      "needs": "装完还得自己配什么（没有就写 null）。"
    }
  ]
}
```

几条规矩：

- **只有 GitHub 链接与我们自己写的说明**。清单里**不放**任何第三方内容（正文、脚本、
  许可证正文都不放）——内容由工具现抓，落在数据目录里，不进代码仓库。
- **`slug` 与 `sourceRef` 不写进清单**：它们由共用的取包规则
  （`@agentdeck/skill-source`）算出来，与 daemon 装技能时逐字相同。写死在清单里
  就会漂移——**远端列出一个 daemon 装不进来的东西**，使用者点下去才失败。
- `needs` 是给使用者看的："装完还得自己配什么"。装之前就说出来，比装完才说好。
- 加一条之前**先核对路径**（`anthropics/skills` 的 `pptx` 在 `skills/pptx` 而不是
  仓库根）。路径写错的表现是同步时那一条失败、整次同步不落盘——不会静默少一条。

## 仓库里混着别的文件时：`include` / `exclude`

**技能格式本身没有"哪些文件是必须的"清单**（`SKILL.md` 的 frontmatter 不声明依赖），
所以只能**声明**或推断。我们选声明：维护者读一次仓库、把决定写进清单，机器只执行。

```json
{
  "url": "https://github.com/lewislulu/html-ppt-skill",
  "exclude": ["docs/**", "scripts/verify-output/**"]
}
```

- 图案是**相对技能目录**的 glob：`**` 跨目录、`*` 不跨、`?` 单字符；
- `include` 是白名单（只取列出的，`SKILL.md` 始终保留）；
- 两条硬规矩：**`SKILL.md` 不许被排除**（写错了当场报错），图案不许是绝对路径或含 `..`；
- 排除是**在下载之前**剪枝的（省流量、避开限额），目录图案会整棵子树剪掉、**连列目录都不去**；
- 被排除的东西**逐个列出来**：同步日志一行、装进来的记录里一条（`ignored`）、
  目录条目上一个 `excluded` 字段 ⇒ 界面在**装之前**就显示"内容不完整：跳过了 N 项"；
- 改过排除图案之后**不复用旧内容**（否则会出现"我明明加了 exclude，怎么还是旧的那份"）。

### 为什么不做"自动判断哪些必须"

真跑两个"整仓即技能"的仓库量过（2026-10），**任何单一自动判据都会判错**：

| 信号 | 抓到了什么 | 单独用会错在哪 |
|---|---|---|
| 被 `SKILL.md` 引用（含只写文件名的情况）+ 往下一层 | `guizang-ppt-skill`：`references/` 11 个**全被引用**；`assets/` 13 个里只有 3 个（两个模板 + `motion.min.js`）；超限的 3.5 MB 展示图与背景图**既没被 SKILL.md 提到、也没被模板引用**（扒了 `template.html` 查过） | 动态拼路径的抓不到 |
| 约定目录（`scripts/` `references/` `templates/` `assets/`） | `html-ppt-skill`：`assets/` 70 个**全部**被引用（所以"assets 一律可丢"是错的） | **垃圾也藏在约定目录里**：同一个仓 `scripts/` 58 个文件 5.4 MB，只有 1 个被引用——其余是 `scripts/verify-output/**` 的测试产物 |
| 垃圾图案（`docs/` `examples/` `**/verify-output/**` `.github/` 大图） | 两个仓里 **8 个超限文件全被抓到**，且没一个是技能引用的 | 有的技能真把内容放 `docs/`（不能全局写死） |

所以本工具提供的是**声明能力**，而不是"替你挑一个算法"。顺带一条策展建议：
**优先收「`<repo>/skills/<名字>/`」这种形状**的条目（目录里就是那个技能），
"整仓即技能"是少数难形状，用 `exclude` 单独处理。

## 配额：这条命令要花多少次 GitHub API 调用

全部打在 `api.github.com` 上（GitHub 对**匿名**请求限 **60 次/小时/IP**）。每条技能要：

1. **列目录**（`/repos/{o}/{r}/contents/{dir}`）——技能是个目录，里面有 `SKILL.md`
   与可能的支持文件（`scripts/`、`templates/`…）。**文件名猜不出来**：猜漏一个，
   技能就是坏的，而且**坏得很安静**（界面显示"已安装"，跑起来才发现少东西）。
   ⚠️ **每一个子目录还要再来一次**（子目录里的文件名同样猜不出来）：所以调用数取决于
   那个技能的目录树有多深，而不是"一条技能两次"。
2. **取版本**（`/repos/{o}/{r}/commits?path={dir}&per_page=1`）——目录要说得出
   "有新版本了"，就得有版本号可比。**这一次是目录独有的**：daemon 装一条 GitHub
   链接时版本落 `null`，共用取包规则里根本没有这段代码。

文件内容本身走 `raw.githubusercontent.com`，**不计入**这 60 次。

**实测**（2026-10，真跑一次单条清单）：

```
清单：1 条
✓ pptx（52 个文件，anthropics/skills@main:skills/pptx）
GitHub API 调用：11 次
```

**一条 = 11 次**，不是两次：`pptx` 有 52 个文件、目录树里 9 个目录。同一天又量了一条
小技能 `research`（2 个文件、1 个子目录）= **4 次**。两条都符合"**盘上留下的目录数 + 2**"
（根目录各一次 + 每个子目录各一次 + 取版本一次）——所以真正决定开销的是**目录树有多深**，
而"一条技能两次调用"那种算法会低估一个数量级。

> ⚠️ **这一节原来是错的**：早先按设计意图写成"每条 2 次、12 条 24 次"（当时没实测，
> 只数了"列一次目录 + 取一次版本"）。真跑一次才发现差了一个数量级——而 12 条的清单
> 按 60 次/小时**根本装不下**。所以下面是按实测改过的结论。

| 情况 | 需要调用 | 匿名（60/小时）够吗 |
|---|---|---|
| 12 条、每条目录都不大 | 24 次（理想下限） | 够 |
| 12 条、含 `pptx` 这种大技能 | **100 次以上**（实测 `pptx` 一条 11 次） | **不够** |
| 一条条手装（12 条） | 每条约 1+目录数 次 | 分散在多次点击里，基本撞不到墙 |

所以本工具**每次运行都会打印实测花掉的次数**（不是文档里那句"大概多少次"，是数出来的）：

```
GitHub API 调用：11 次（匿名限额 60 次/小时；文件内容走 raw.githubusercontent.com，不计入）
```

（走加速器时这一行会换成"经加速器转发的 API 调用：N 次（不占本机那 60 次）"——
主机名不再是 `api.github.com`，只按主机名数会数成 0，那会让人以为什么都没请求。）

**撞墙了怎么办**（这是设计里认真处理过的一种情形）：工具**第一条失败就停**（不把剩下
的条目挨个试一遍——撞限额时后面每条都是同一句话），并且**已抓到的那几条会留在断点目录里**
（见下），**已发布目录一个字都不改**（P7）。于是"撞墙之后重跑"是**真的**有意义的：
下一轮只补缺的那几条，配额不会白花，几次运行就能收敛。想强制重新下载用 `--refresh`。

### 走加速器（可选，第三方）：既解决下载不稳，也不再受本机那 60 次限制

国内直连 GitHub 经常失败。命令行加 `--github-proxy`（**裸写就够了**，值可省略）或者
环境变量 `AGENTDECK_GITHUB_PROXY`，就会把每个 GitHub 请求转给加速器：

```bash
pnpm run sync-skills --github-proxy            # 不带地址 ⇒ https://gh-proxy.com
pnpm run sync-skills --github-proxy https://别的加速器
pnpm run sync-skills --github-proxy off        # 这次直连（覆盖环境变量）
# ⚠️ 走 GitHub 加速器：gh-proxy.com
#    它能看、也能改转发过来的内容（第三方进了信任链）；凭证不会交给它（它自己有），
#    本机那 60 次/小时的匿名限额也不再适用。
```

**实测**（2026-10，3 条清单：`pptx` + `docx` + `research`）：一次跑完，**111 个文件**全部落地，
版本号也记上了——直连时这 3 条要 ~28 次调用（还容易断），走加速器**不占本机配额**
（加速器自己带凭证，实测它给的额度是 5000 次/小时）。

三条硬规矩（都在 `packages/skill-source/src/skill-source.ts` 里写死了，有测试钉着）：

| 规矩 | 为什么 |
|---|---|
| **只代理 GitHub 自己那三个主机** | 你填的其它地址照样被白名单挡在外面：加速器不会变成"访问任意地址的跳板"（那正是白名单存在的理由） |
| **走代理时不带我们的 token** | 代理自己带凭证（实测 5000/h），而 token 是秘密——不给第三方看，也不赌它会不会转发 |
| **默认关，显式指定才开** | 加速器是**第三方**：它能看、也能改转发的内容。这种事不该由工具替你决定。⚠️ "裸写旗标就用 gh-proxy.com"只是**省打字**，不是"默认开"——不带这个旗标仍然直连 |

⚠️ 代价如实说：**加速器就是链路上的中间人**。它适合"直连不稳、内容又本来就是公开仓库"的场景；
`daemon` 那条路（界面里从 GitHub 链接装技能）用 `pnpm run daemon --github-proxy` 开同一个口子
（同样可以裸写；`off` 直连）。⚠️ 环境变量 `AGENTDECK_GITHUB_PROXY` **只对同步工具有效**——
守护进程的配置写在命令行上，而不是靠 shell 里恰好 export 了什么。

### 断点目录（`<out>.partial`）：撞墙之后重跑为什么真的能收敛

⚠️ **别被"1 小时窗口"误导**：那条规则读的是**已发布目录**里的索引，而那个文件只在
**整轮成功**时才被写。只靠它的话，撞限额时的真实循环是"抓到第 5 条 → 全部丢弃 →
下一轮从零开始 → 又撞在同一处"，**12 条在匿名限额下永远跑不完**。
（这一条我先前说错过：当时我说"重跑会收敛"，其实不成立——2026-10 使用者追问才发现。）

所以有两个目录，分工明确：

| 目录 | 是什么 | 失败时 | 成功时 | 复用规则 |
|---|---|---|---|---|
| `<out>`（已发布） | 界面读的那个公共目录 | **一个字都不改** | 原子替换 | 1 小时窗口内不重抓 |
| `<out>.partial`（断点） | 已花配额抓到、还没发布的内容 | **留着** | **删掉**（内容已发布） | **粘性**：只要有就不重抓 |

两条规则的口径**刻意不同**：已发布那份过期就重抓（1 小时，按你的要求）；断点那份**跨小时也留着**
（它是已经花掉配额换来的，丢了只能再花一次——那正是这个目录存在的理由）。

于是"撞墙 → 等配额恢复 → 再跑"是一条真的收敛路径：

```
第 1 小时：✓✓✓✓✓✗ 撞墙   → 已发布目录没变，断点目录里有 5 条
第 2 小时：⏭⏭⏭⏭⏭✓✓✗ 撞墙 → 断点里有 7 条（前 5 条 0 次调用）
第 3 小时：⏭⏭⏭⏭⏭⏭⏭✓✓✓✓✓✓ → 全部发布，断点目录被删掉
```

`--refresh` 与 `--dry-run` 都**无视**断点：前者是"全部重新下载"，后者是逐条真抓一遍
（而且一个字都不写，连断点目录都不建）。

撞墙时的表现是**逐条报原因、目录一个字都不改、退出码非 0**，并且那一行会告诉你
这次花掉了多少。想彻底不受限：给一个**不勾任何 scope** 的 personal access token
（公共仓库只读不需要权限），限额变成 5000/小时：

```bash
AGENTDECK_GITHUB_TOKEN=xxx pnpm run sync-skills
```

⚠️ 别用 `export NODE_TLS_REJECT_UNAUTHORIZED=0` 之类的办法"让它跑起来"：这条命令下载的是
第三方内容，而内容完整性的信任只剩 TLS 那一层（没有哈希校验）。关掉它等于把那一层也去掉。

## 失败语义（P7：宁可失败，不可静默降级）

- **任何一条抓不到 ⇒ 整个目录一个字都不换**，退出码非 0 并报出原因。
  半份目录比旧目录更糟：使用者会点到一个"看起来能装、其实是半截"的条目，
  而维护者以为同步成功了。
- **第一条失败就停**（2026-10 使用者要求）：剩下的条目**不再挨个试**，并如实报
  "后面 N 条没有再试"。理由很实际——撞限额时后面每条都会是同一句话（"匿名次数
  用完了"），把一屏同样的话刷出来既看不清重点，结论也不会变（第一条失败时就定了）。
  修掉这一条或等上游恢复，再跑一次即可；**已抓到的部分留在断点目录里，不会白费**
  （见上面那节）。
- 替换是**原子的**：先全抓到内存、写进 `catalog-skills.staging-<pid>`，全部成功
  才 `rename` 换上去（换不动就回滚）。中途任何失败都会清掉 staging。
- **单条失败 ≠ 静默跳过**：清单里那一条会出现在失败清单里（含 URL 与原因）。
- 版本取不到（GitHub 抽风、限额）**不算失败**：版本记 `null`，界面如实说
  "无法判断是不是同一份内容"，而不是瞎比大小或假装是最新的。

## 目录布局（远端服务读它的方式）

```
<catalog-skills>/<slug>/SKILL.md     ← 内容（+ 支持文件）
<catalog-skills>/.sync.json          ← 元数据：slug、sourceRef、version、fetchedAt、files
<catalog-skills>.partial/            ← 断点目录（同一个布局；只是"还没发布"）
```

⚠️ 元数据放在**技能目录旁边**，不能放进去：共用取包规则会把技能目录里每个文本文件
都当成**支持文件**收走，JSON 会被装进使用者的技能里。

默认写到 `~/.agentdeck/remote/catalog-skills`（远端服务**默认**读的就是这里）。
远端用 `--data-dir` 改了数据目录时，这里也要用 `--out` 指到那儿——工具每次都会打印
它写到了哪儿，就是为了让这件事可核对。目录落在数据目录里、**不在代码仓库里**。

## 它自己的形状：为什么要注意 tsconfig 与测试 glob

`tools/` 下的东西**不吃** `packages/*` / `apps/*` 那两条自动发现规则。所以：

- `tsconfig.json` 的 `include` 显式加了 `tools/*/src/**/*.ts`——不进类型检查的代码
  可以烂掉，而"没被检查"这件事本身不会报错；
- 根 `package.json` 的测试 glob 显式加了 `tools/*/src/**/*.test.ts`——不然这里的
  测试**永远不跑**，而"没跑"看起来和"通过"一模一样；
- `pnpm-workspace.yaml` 显式列了这个目录，只为了 pnpm 把 `@agentdeck/skill-source`
  接好（它不参与打包，也不是任何 app 的运行前提）。
