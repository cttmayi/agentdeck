# tools/layout-probe — 界面布局检查

`tsc` 与 `svelte-check` **看不见布局**。类名写对、模板合法，但"两栏有没有真的并排"、
"窄屏返回按钮有没有出现"、`.main:has(> .split-layout)` 有没有生效——这些只有浏览器量得出来。
这个项目里已经出现过两次"接口都在、就是没接线"的缺陷，而布局类的缺陷更隐蔽：页面看起来
能打开，只是排错了。

这个工具就是补这一格：**把真应用放进同源 iframe，用真实点击驱动它，把浏览器的计算结果
读出来，与期望值逐条比对，不对就红。**

## 用法

```bash
pnpm run build:web            # 它量的是 apps/web/dist 里的真产物
pnpm run probe:layout         # 量一遍并断言；全过退出 0，有一条不过退出 1

# 想自己用浏览器看一眼（会留下 daemon，用完 kill 掉它）：
pnpm run probe:layout -- --keep
```

它**不在 `pnpm run check` 里**，这是有意的：它需要真的 Chrome 和一个真的 daemon，塞进
测试套件就等于让所有测试依赖"这台机器装了浏览器"（NFR-T-01 那条线反过来走）。改布局时跑它。

## 历史：那 7 段是怎么过期的（2026-10 现场记录）

2026-10 那次「技能/工具安装面板改成主区面板」跑探针时发现的：**探针整体已经跟不上界面了**。
542 条断言里 **363 条绿、74 条红、105 条没量到**（542 = 那次基线的 537 + 「查看器支持视频」
那一轮新加的 5 条，那 5 条全绿）（判据见下面「怎么复现」；红按段落分：
新建任务的三步链 28、审核标准 13、新建任务 9、智能体 8、新建表单/设置 4、工具 3、
迁移 2、老信息清理 2、行动权限空态 2、语言切换 1、配过但不可用 1、任务 1）。

**这不是探针本身坏了，也不是老早就有的**：HEAD（上一个提交）上的探针与 HEAD 上的代码是
对得上的（`.chain-step`、`hero` 这些锚点在两边都在），所以这些红**全部**是这几次界面改造
欠下的账——改造当时被接受了，而探针没跟着改：

| 段落 | 为什么过期 | 现状锚点 |
|---|---|---|

| 工具（D40） | 「执行者/审核者的详情里有工具段」那一对断言随挂载能力一起撤销 | `tools.executorHasNoToolsSection` |

**已经随手补过的**（这一轮之内，共 358 条绿里的这些）：
- 智能体那一段的窄屏出口（`.back` 按钮已经不存在 ⇒ 改成"点侧边栏真的出得去"，与任务页同一条判据）；
- 技能 / 工具两段（安装抽屉 → **主区面板**那一套 12 条判据，见上面「它量什么」）；
- 导航项数（侧边栏现在是**六项**：聊天 / 任务 / 智能体 / **智能体组** / 技能 / 工具）；
- 探针自身两处加固：`cs()` / `click()` 拿不到元素时**记一条、继续往下量**（原来 `click(null)`
  抛 TypeError 会把整个 `main()` 打死，报告里于是有 500 多条"没量到这个值"，而真因只有一个、
  藏在第一个异常里）；每段开头 `publish(false)` 先把事实写进 DOM（跑不完也看得到跑到哪）。
- **音视频那五条**（2026-10，查看器支持视频那一轮）**是新加的、全绿**：夹具用 `ffmpeg`
  现造一段 160x120 的 WebM/VP8（`clip.webm`）+ 一个 mp4（`clip.mp4`，只用来量类型与 Range）
  + 一个**手写 WAV**（`tone.wav`，不依赖 ffmpeg）+ 一个**冒充 `.mkv` 的垃圾文件**
  （`broken.mkv`，必然解不出来）。⚠️ 视频那条判据是 **`readyState >= 1`**（浏览器真的解出了
  元数据），不是"`<video>` 元素在不在"——一口空黑框正是它要挡的东西；`Range` 那条从探针页
  自己 `fetch` 一次，要 **206** + 正确的 `content-range` + 只有那 100 字节，再整份取回来
  逐字节比对。⚠️ 用 **VP8/WebM** 是因为 Chrome 与 Chromium 都解码得了（H.264 只有 Google
  Chrome 的官方包带），这样这条判据不取决于探针落在哪个二进制上。

⚠️ 重对齐时的两条纪律（这一轮踩过）：
1. **夹具也要跟着改**。`run.mjs` 造三步链夹具时往 agent 上写 `allowedActions` /
   `actionParams`，而这两个字段已经从 `Agent` 上撤掉 ⇒ daemon 直接 **400**，夹具没造出来，
   那一组于是全量"空过"。动作权限与固定参数现在只能挂在**智能体组**上。
2. **别把虚拟时间预算耗光**。每一条超时的 `until()` 吃掉 15s **虚拟**时间，而
   `--virtual-time-budget=300000` 是硬的：老段落一起超时 ⇒ 预算在跑到一半时用光 ⇒
   `#out` 永远停在 `pending`，症状是"探针没在超时前给出结果"，看着像探针卡死。
   现在每个段落开头都会 `publish(false)` 先把手上的事实写进 DOM，所以**跑不完也能读到
   "跑到哪一段、量到了什么"**。

### 怎么复现上面那份判据

```bash
# 两把闸一起调大：过期断言每条超时吃 15s **虚拟**时间，默认那 300s 会被吃光，
# 于是 dump 里 `done` 不是 true、看着像探针卡死（调大之后这一趟是**跑完**的）。
PROBE_VIRTUAL_MS=900000 PROBE_TIMEOUT_MS=900000 pnpm run probe:layout || true
node tools/layout-probe/check-facts.mjs                 # 拿 dump 里的事实比对 CHECKS（跑不完也读得到）
```

⚠️ 上面那张表是**历史**：那些红已经逐条对齐完了（现在 570 全绿）。它留着是为了"下次遇到红时
先分辨是哪一类"——断言住在不存在的宿主上 / 界面重做过 / 断言滞后 / 探针等错了（虚拟时间）。

`check-facts.mjs` 是这一轮补的小工具：它从 `dump.html` 里读出探针**当下**发布的事实，
与 `run.mjs` 的 `CHECKS` 逐条比对，并分成"绿 / 红 / 没量到"三类——过期段落把预算耗光时，
这是唯一能看清"到底哪几条真红"的办法（整趟跑不完就只剩一句 `pending`）。

## 它量什么

- **智能体**：主从布局两栏宽度（26rem 清单 + 剩余给详情）、点一条进 `with-detail`、
  选中态、宽屏隐藏返回按钮、窄屏只剩一栏且返回按钮出现、返回后回到列表、
  `.main:has()` 生效（主区不整体滚动、padding 归零）、Runtime 卡片字段没丢；
- **任务清单**：同一套主从；从没跑过的那行必须先显示「执行中 + 还没开始执行」；
  整份渲染结果里「等待审核」出现 **0** 次（使用者点名要去掉的重复字样）；
- **技能**：每行有「卸载」（D38）；两代老结构都不再出现（`.install-panel` / `.drawer`）；
  **安装面板在主区里**（2026-10 起）：`.main-panel` 落在 `.main` 内容盒里、左右边缘与主区对齐、
  `position` 不是 fixed/absolute、没有遮罩、**取代**列表（开着时表格不在 DOM 里）、头部有
  **一直可见**的「← 返回技能列表」（点它回到列表、表格回来）、底部是主操作「检查并安装」、
  页签条里没有与面板头重复的「关闭」、Esc 能关；
  ⚠️ 这几条**都是照"它不是对话框"写的**：没有遮罩、没有 `role="dialog"`、没有浮层定位——
  旧那几条（"抽屉在右边 / 宽 46rem / 有遮罩 / 抽屉没把列表吞掉"）随那次改动一起作废；
- **导航与工具（D40 / D49）**：侧边栏**恰好六项、顺序逐项比对**（聊天 / 新建任务 / 任务清单 /
  智能体 / 技能 / 工具；★ 原来那句"恰好四项"从 D40 起作废、D49 又把「聊天」加在最前面，
  于是「工具」从第 5 项变成第 6 项。`view.ts` 的 `VIEWS` 与 `Sidebar.svelte` 的 `ITEMS`
  是两处联动，少动一处不会报错，这几条就是那个守卫）。
  ⚠️ **只数个数 + 只看末项是不够的**，两次变异实测：把「工具」插到 Skills 前面 ⇒
  `shell.navLastItem` 红（数个数绿）；而**把 Skills 那一项的文案悄悄换成「工具」**⇒
  项数还是 6、末项还是「工具」，**两条全绿**——一个非末项凭空消失也照样通过。
  所以补了 `shell.navItems`：量**整串顺序**并逐项比对，顺序错 / 中间少一项或换一项 /
  多出第 7 项三种都红。列表里那个夹具工具在、
  **动作数**对得上、**版本与来源**说得出；点开一行看得到组内动作（契约值
  `<slug>.<动作名>` 原样显示）、`reversible: false` 标「不可回滚」、参数分**平台绑定**
  （写明"模型看不到也填不了"）与**模型可填**（显示类型与上限）两组；安装面板是**主区里的就地面板**
  （`.main-panel`，与技能页同一套判据：在主区内容盒里、无遮罩、取代列表、返回入口一直可见、
  Esc 能关），**装一个坏包**时显示 error 与**多行 detail**（并被 `pre-wrap`
  保持多行）外加按错误码给的建议，**装一个好包**时说清装进来了什么（动作 + 文件）且列表
  立刻多一条；**两边详情里都没有「工具」段**（挂载能力已撤：工具落成审核者的「行动权限」；
  那条写入口现在由 `tools-api.test.ts` 覆盖）；「行动权限」那一栏里
  能勾到**已装工具的动作**（值是契约值，旁边带 `summary`），而且那些勾选项**全部**是
  已装包的动作（slug 取自接口）——D41 之后那一栏里**没有**内置动作那一组、也**不预勾**
  任何东西。
  夹具由 `run.mjs` 造**三个目录**：`probe-tool`（两个动作，其中一个不可回滚 + 不支持预演）、
  `probe-tool-ui`（给抽屉里那次真实安装用——同名会被 `probe-tool` 自己挡住，
  量到的就变成"同名冲突"了）、`probe-broken`（清单合法但入口不在包里 ⇒ `missing_entry`
  的 detail 是**两行**，"多行 detail 一起显示"只有它量得到）；前两个路径经 URL 传给探针页，
  因为抽屉里那次安装是"真的往输入框里打字"驱动的；
- **迁移（D38）**：夹具里有一个"只挂 skill、没有内联标准"的审核者（老数据的形态），
  探针走一遍「把这份判断依据并进「指令」」：按钮在 → 点了之后正文真的进了「指令」、
  那一栏跟着改口（不再说"没有写「指令」"）、挂载清空、那句"沿用挂载的 skill"的提示消失；
- **判断依据与行动权限（D37/D40 收口，2026-09 收口到「指令」）**：这一组量的是**一次删除的两半**——
  ① 详情里**没有任何一行叫「审核标准」**、也没有「用什么标准」那段标题；② 老数据那份正文与
  「并进「指令」」的入口**都在「指令」那一栏里**（只量一半都会假绿：只量①，把正文一起删掉也绿；
  只量②，那一段还在也绿）。而**"判完允许动什么"是审核者自己的一个独立段**
  （「行动权限：判完之后允许做什么」），显示的是"允许触发的动作"那一行里的动作清单（契约值原样），
  且**动作 chip 不在承载判断依据的那一栏里**（同一件事只能有一个出处）——这几条都**先取出那一段
  的容器**（按 `h3` 的标题认）再在容器里量，不是只把选择器换个地方了事；**执行者的详情里没有
  这一段**（它的能力是工具，与"审核者没有工具段"对称）。
  只读态那一行显示的东西有一条**关系型**判据：页面上那些 chip 的值**逐字等于**接口回给这个
  agent 的有效 `allowedActions`（含老字段的回退）——D41 之前量的是"chips 里有 `comment.create`"，
  那个名字已经不是任何动作了，留着它等于把断言钉在旧现实上。
  新建表单里执行角色下行动权限栏**不出现**（更不会预勾），切到审核角色才出现**一栏**：
  行动权限 = **已装工具的动作**（每一组按包分组，旁边带清单里的 `summary`），而**标准不再单独设置**
  （只有一句「判断依据写在上面那条「指令」里」的说明，容器 `.standard` 一处都不该有），
  而且这一栏里**没有**内置动作那一组（`.action-picker` 一处都不该有）、**一个都不预勾**、
  出现的每一个勾选项都必须是已装包的动作（slug 取自接口回的已装列表）——最后这一条才是
  "动作只能来自工具包"在界面上的落点：只量"没有那一组"的话，把那一组换个类名重新长出来照样绿。
  另有**写入口/绑定**的检查（同一件事现在由「指令」那一栏承担：那个"已写"徽章随标准编辑框一起
  不存在了）、在权限那一栏**真的勾一个工具动作**之后
  写下正文、那一勾仍在（两份草稿不互相覆盖；D41 之前量的是"预勾的那一档还在"，预勾没有了之后
  照原样量就会**空过**）、以及在详情里勾那个工具动作 → 保存 → 详情里多出那一条并**带着它的
  `summary`` → 且**以 `/api/agents` 回的那份为准**真的变了（不是只把界面画对了）；
  ⚠️ **老形态那两条提示要一起看得见**：「指令」那一行说"沿用挂载的 skill 当标准（老配置）"、
  行动权限那一段说"能触发的动作也来自这些 skill（老配置）"——"标准与动作都还是老形态"
  只有两句合起来才说得清，所以探针量的是**同一次渲染里两条都在**（分属两段，任何一条被
  挪走或被条件挡掉就只剩半句话）。这是只读兜底链（agent → 标准 → **挂载 skill**）在界面上
  的落点：一个都没勾、却仍然能触发动作，必须说得出出处；
- **"配过、但现在解析不出来"的动作（D41 收尾）**：老数据里存着平台当年那六个内置动作名
  （已经整组移除），或者提供它的工具包被卸载了——这时界面必须是**三件事一起**成立：
  ① 契约值**照原样留着**（静默过滤掉等于抹掉"配过"这件事）；② 旁边明说它**当前不可用**
  （照原样显示而不加标记，它就跟一条真的能触发的动作长得一模一样）；③ 编辑态里**列得出来、
  去得掉**（它不在勾选框里，不列就是"看不见"；一保存又被服务端拒，而错误里点名的那个名字
  在界面上根本不存在——那是个死胡同）。
  现场是**真造出来的**，分两个阶段、**每一步都走真入口**：
  · **阶段 A（保存被拒那条路）**：在界面上把 `probe-tool-ui.ping` 勾给审核员并保存（那个包
    装着，写入口收）→ 走接口把 `probe-tool-ui` 卸载 ⇒ 那条权限变成"配过、但没有出处" →
    刷新界面的 `$tools` → 再打开编辑（那条**列出来**了）→ 勾一个**仍然可用**的动作再保存
    ⇒ 那一份 patch 里带着它 ⇒ **400**。这时量四条：服务端**真的拒了**（拿同一份名单直接问
    接口当基准）、页面上那句话与接口回的**逐字相同**（不吞掉、也不自己概括）、界面**还停在
    编辑态**、那条名字**还在草稿里**（被拒之后不许静默剔除）。然后是出口：只去掉一条保存
    ⇒ **仍然被拒**（服务端规则是"名单里只要还有一条没出处的就不收"），逐条去掉之后再保存
    ⇒ 真的存进去了（以接口为准）。
  · **阶段 B/C（一个包都没装）**：把剩下的包全卸载 ⇒「行动权限」那一栏的空态，以及只读态
    那一行/编辑态那一栏对那几条没有出处的权限的完整表现。

  ['comment.create','issue.add_label']`，而写入口**按设计拒绝裸名**、并且**刻意忽略**那个老字段

  空数组与"真的一个都没装"长得一样，不加这道闸会把配得好好的权限全标成不可用）；

  "点「移除」"）分开写、也分开量**：用同一句话会让只读态的使用者去找一个不在那儿的按钮。
- **行动权限的空态（D41）**：一个工具包都没装时，那一栏必须**说明白**"还没有装工具包 ⇒ 现在
  没有任何动作可授权"并**指向「工具」页**（只读态那一行与编辑态那一栏**同一句话**），而不是
  留一片空白、也不是显示一个空的分组标题（标题在、下面什么都没有是最坏的一种画法）。

  而且选择器里**只有执行者**。夹具需要**两个执行者**（`run.mjs` 里造，理由见那边注释）；
- **新建任务**：至少不白屏；

  ③ 现在是**可勾的**（按工具包分组的勾选框，形状照抄智能体页的「行动权限」）：

  的是那个审核者当前生效的那几条**（夹具里 1 个：`probe-tool.clean-notes`）；每个框旁边是契约值
  原样 + 工具清单里的 `summary`（**逐字**与接口那一份相同）。
  ★ "只对这一次任务生效"那句**只在改过之后**出现：默认态**不许**有它，取消一个勾**必须**有它，
  再勾回来（勾选结果又与审核者那份一致了）**必须消失**——判据是集合相等，不是"碰没碰过"。
  ★ ③ 的**四个档**各量一次：有动作 ⇒ 勾选框；有审核者但零动作（夹具里专门有一个）⇒ 框照画、
  **一个都不勾**；工具清单没到（让 `/api/tools` 真的失败 + 在「工具」页点**它自己的**刷新，那一刻
  store 里还留着上一次取到的清单）⇒ **一个框都不画**，并且说的是"工具清单还没到"而**不是**"现在
  没有一个能用的动作"（后者是关于**使用者自己的权限**的一句假话）；daemon 兑现不了这一栏的覆盖

  只读、画 chip**，而 ② 那一栏**没有**跟着退化（两个标志是两份契约）。
  ② 上选了非「跟随」的两档都会多出"只对这一次生效"那句；③ 的两个空态**分开量**：
  有审核者但没动作 ⇒ "判决只会给出结论，**不会触发任何操作**"，没有审核者 ⇒ "这次没有审核者…
  **既不会有判决，也不会有任何动作**"，**并且后者不许照抄前者那句话**（那一档连判决都没有，
  说它就是假话）。
  ★★ **端到端是这一组的重点**：提交**三次**，每次之后**从接口**把那条新 run 读回来。② 那两条读
  `GET /api/runs` 的投影：停在「跟随」⇒ `reviewer.mode === 'follow'`，切到「不自动审核（这一次）」
  ⇒ `'none'`——`follow` 与 `none` 在接口上**长得不一样**，所以它们同时钉住了"跟随不能说成 `null`"
  （写成 `null` 就是 `none`：使用者以为自己只是照旧，实际把审核关掉了，而界面一切正常）。
  ★ ③ 那两条读的是**落库原文**（`GET /api/runs/<id>`，列表接口里根本没有这个字段）：**没碰 ③
  就提交** ⇒ 原文里**没有 `allowedActions` 这个 key**（= 跟随那个审核者的长期「行动权限」；
  写成 `...(x ?? [])` 那种"总是带"的实现会给出 `[]` ⇒ 红），**一个都不勾再提交** ⇒ **键在、
  值是 `[]`**（"这一次一个动作都不许触发"）。两条合起来钉死"**省略 ≠ 空数组**"：这两种写错法的
  后果分别是"使用者的一次收紧被静默丢掉"与"他什么都没做却被冻死了那个审核者的权限"，而两种
  情况下**界面都一切正常**。
  夹具是 `run.mjs` 在**装完夹具工具包之后**造的三个 agent（两个审核者 + 一个执行者，见那边注释
  里的顺序理由），三个 id 与动作名经 URL 传给探针页；那个执行者的 runtime 刻意是 `generic`
  （命令 `agent-cli` 不存在）⇒ 这三条 run 会立刻失败，探针不会真的拉起一个模型去干活。
  ⚠️ 这一段还必须**自己收拾现场**：`location.hash = '#/new'` 在已经是 `#/new` 时是空操作，
  组件不会重新挂载，而 ② 选的那一档是**组件状态**——第一次跑就是这么红的：提交出去的那条 run
  带着上一次留下的"不自动审核"，`reviewer.mode` 是 `none`，**一条真 bug 的样子**。修法是进这一页
  之前先离开它，并多量一条"提交①之前 ② 上到底是哪一档"（只观察、不设置）；
- **新建表单 / 设置（右侧抽屉）**：按钮文案是「新建」与「设置」（不是"第一句话设置"）、
  点开后是**贴右边的抽屉**（有遮罩、46rem 宽、**不在主从两栏里**）、关闭后栏头高度**不变**、
  内部没有横向溢出、主操作常驻视口内、Esc 能关；设置抽屉是**分段容器**（`.drawer-section`，
  现在一段：第一句话模版）+ 一个共用的「保存」；段里三个页签（执行 / 审核 / 聊天）**各自独立**、
  填入默认模版真的带变量、**保存真的落库**（直接问接口）、重开看到的就是存下的那份。
  另外钉一条**否定事实**：新建表单里**不该**再有模版那一栏（它是通用配置，不是每个 agent 一份）。
- **界面语言（D39）**：顶栏有语言切换器、默认是 `zh`；切成 English 之后**导航、顶栏按钮、阶段
  短标签、看板列头与说明**都真的变英文（这一步是对"推导层只给**文案键**"的端到端验收：

  探针刚走真实写入口把它勾上去；D41 之前这里量的是 `comment.create`，那个名字已经不是动作了，
  再量它就只能量到一条老数据里碰巧留着的字符串）；最后一件事是
  **写回服务端**（界面与 prompt 里那句语言指令必须同源）。

  盖住右栏，一版只有 358px 宽、模版编辑器没法用）。还有一条量**输入框的高度**：空的模版
  也得有 300px 以上的下限，填进几十行的那份之后要**跟着长高**（用"内容的行数"兜住这条
  断言，免得框本来就是空的也过）。

## 三条边界（都是刻意的）

1. **基本不造 run —— 只有一个例外。** 造 run 就会去调真的 CLI，所以夹具里那些任务
   （一条长标题、一条短标题）都不指派给任何人，验的是**布局与结构**，不是"跑起来之后
   长什么样"。**例外是「新建任务的三步链」那一组**：那里要证明"界面上选的"与"发出去的
   请求体"是同一件事，而这件事只有真的点一次「创建并派发」、再从接口上把那条 run 读回来
   才看得见（`reviewer.mode` 的三态）。那三条 run 的执行者 runtime 是 `generic` —— 它的
   命令 `agent-cli` 不存在，run 会**立刻**以 ENOENT 失败，**不会**拉起任何一个真实的模型
   去干活；这条断言的判据是那条 run **记录**上的三态，与它跑得起来跑不起来无关；
2. **数据是确定性的**：一次性 data-dir 首启会播种一对 agent 与一个审核模板，
   断言据此写，不依赖运行者自己的数据；
3. **只写仓库内**：数据、工作目录、Chrome profile、抓回来的 DOM 全在
   `.cache/layout-probe/` 下（跑完留 `report.json` 与 `dump.html` 供排查）。

## 五个坑

- **探针要收拾自己的现场。** 界面上有些状态**存在 `localStorage` 里**（任务视图的列表/看板
  模式就是），它会带到同一轮的后面、甚至带到下一轮。D39 那次就踩了：语言那一节按
  `.task-row` 抓行，可前面的"看板"一节把模式留在了看板 ⇒ 一条行都抓不到，症状是"两个值为
  `—`"，看起来像选择器改了。**修法不是放宽断言**，而是切视图前显式切回已知状态、结束时还原。
- headless Chrome 打完 `--dump-dom` **不会退出**，所以这里是"后台跑 → 轮询输出文件 →
  再杀"，不是"等它结束"。**两把闸都可调**：`PROBE_TIMEOUT_MS`（真实时间，到了就杀 Chrome、
  dump 被截断）与 `PROBE_VIRTUAL_MS`（Chrome 的 `--virtual-time-budget`，到了就 dump，
  探针可能还没跑完）。有过期断言在超时时，两把一起调大才看得到更多段落：
  `PROBE_VIRTUAL_MS=900000 PROBE_TIMEOUT_MS=900000 pnpm run probe:layout`；
- 杀 Chrome 只按**本次专用的 user-data-dir** 匹配。早先用 `pkill -f "Google Chrome"`
  把使用者本人的浏览器一起杀掉过，是个事故——不要写宽匹配。
  ⚠️ **Windows 上不能照搬这一句**（2026-10）：那边没有 `pkill`，而且**光杀父进程不够**——
  Chrome 的子进程还活着、还占着那个 profile 目录（下次运行会看到"profile 已被占用"），
  所以走 `taskkill /PID <pid> /T /F`（在 `killChrome()` 里按平台分支）；
- **探针里的 `const` 不能重名**。整个内联脚本是一个作用域，重复声明会让**整段脚本**
  语法错误——而症状看起来完完全全是"Chrome 超时"：`dump.html` 里 `#out` 还是
  `pending`，一条 error 都没有（`main()` 里的 catch 根本没机会跑，因为脚本没被解析）。
  **现在这一步是自动的**：`run.mjs` 起 Chrome 之前先把探针页里的脚本交给 `new vm.Script()`
  解析（`assertProbeScriptParses`），语法错就当场打出"第几行、哪个标识符"并 `exit 2`。
  这道兜底是 2026-10-21 补的——那天给"编辑窗格起点"加测量时把 `cyPaneRect` 又声明了一遍，
  探针连着两次跑满超时、`#out` 停在 `pending`，我先**误判**成"虚拟时钟下 iframe 的 load
  事件会错过"（还写了个补丁，后来撤回了），绕了 20 分钟才回去看脚本本身。
  手工复核仍然可以（读 dump 之前先做，比读 dump 快得多）：
  `python3 -c "import re;s=open('tools/layout-probe/probe.html').read();open('/tmp/p.js','w').write(re.search(r'<script>(.*?)</script>',s,re.S).group(1))" && node --check /tmp/p.js`
- **等待条件要挂在"结构事实"上，不要挂在某句文案上。** 2026-10-21 撞到：审核取消之后，
  断言等的是"结论条里不再出现「审核正在进行」"。可第 2 批把那半句搬进了「过程」里的说明段、
  条上改写成「审核运行中」⇒ 那个条件**恒真**，于是量早了一拍，量到一个"还在取消中"的现场，
  判据红了而界面没错。改成等**取消按钮消失**之后就稳了。
  同理，`text(tab) === '过程'` 也不稳：tab 上会挂问题数徽标（读到「过程3」）⇒ 用 `startsWith`。
- **删/挪判据时数一遍条数。** 同一天我给审阅屏加判据时，用"从 A 的 key 切到 B 的 key"
  这种索引切片删旧的 4 条，结果把夹在中间**刚加的 10 条**一起删了——探针照样全绿
  （少判据不会红，只会"没人问"）。复核办法就一句：
  `grep -c "key: 'crystal\." tools/layout-probe/run.mjs`（改前 61 → 改后应等于 61−4+12=69）。

## 加一条检查

探针（`probe.html`）只上报**量到的事实**，期望值全在 `run.mjs` 的 `CHECKS` 里——"量"与"判"
分开，改期望不必动探针。加检查的步骤：探针里量一个新事实 → `CHECKS` 里加一条 `{view, key,
label, ok}`。

### 一次"看着没坏、其实整垮了"的教训

新建智能体的表单原来渲染在左栏 `pane-head` 里（那个按钮自己管着开不开，表单就画在按钮
旁边）。左栏宽 **416px**，而表单按自己的 `max-width` 画成了 **736px**：横着盖住右栏、
栏头从 167px 涨到 1070px、agent 清单被顶到视口外。**"新建"这个动作把主从布局整垮了。**

而当时代理量了些什么？两栏宽度、卡片内容、选中态、窄屏返回、抽屉……**一条都没红**：
它们没人问"这块东西在不在它该在的容器里、有没有溢出"。补上的就是这一组
（`formInsideHead` / `formFitsPane` / `formOverflowX` / `headGrowthPx` / `varListFitsPane` /
`previewFitsPane`），把表单塞回栏头 + 恢复 `max-width: 46rem` 之后，**5 条同时红**。

所以：**量外观的检查挡不住"位置错了"这类问题**。新加一块界面时，除了"它长什么样"，
还要量"它在谁的里面、有没有越过边界"。

**新加检查后请做一次变异验证**：把对应的实现改坏，确认它真的会红。这个工具自己就抓到过一条
**空过**的检查——"重复字样"那条最初因为表格里一行都没有而永远通过，把「等待审核」塞回模板
照样全绿。
