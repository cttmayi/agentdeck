# tools/layout-probe — 界面布局检查

`tsc` 与 `svelte-check` **看不见布局**。类名写对、模板合法，但"两栏有没有真的并排"、
"窄屏返回按钮有没有出现"、`.main:has(> .split-layout)` 有没有生效——这些只有浏览器量得出来。
这个项目里已经出现过两次"接口都在、就是没接线"的缺陷，而布局类的缺陷更隐蔽：页面看起来
能打开，只是排错了。

这个工具就是补这一格：**把真应用放进同源 iframe，用真实点击驱动它，把浏览器的计算结果
读出来，与期望值逐条比对，不对就红。**

## 用法

```bash
pnpm run build:web            # 它量的是 apps/web/dist 里的真产物
pnpm run probe:layout         # 量一遍并断言；全过退出 0，有一条不过退出 1

# 想自己用浏览器看一眼（会留下 daemon，用完 kill 掉它）：
pnpm run probe:layout -- --keep
```

它**不在 `pnpm run check` 里**，这是有意的：它需要真的 Chrome 和一个真的 daemon，塞进
测试套件就等于让所有测试依赖"这台机器装了浏览器"（NFR-T-01 那条线反过来走）。改布局时跑它。

## 它量什么

- **智能体**：主从布局两栏宽度（26rem 清单 + 剩余给详情）、点一条进 `with-detail`、
  选中态、宽屏隐藏返回按钮、窄屏只剩一栏且返回按钮出现、返回后回到列表、
  `.main:has()` 生效（主区不整体滚动、padding 归零）、Runtime 卡片字段没丢；
- **任务清单**：同一套主从；从没跑过的那行必须先显示「执行中 + 还没开始执行」；
  整份渲染结果里「等待审核」出现 **0** 次（使用者点名要去掉的重复字样）；
- **Skills**：正文里不再有旧的内嵌安装面板、抽屉宽 46rem、有遮罩、主操作贴住底部、
  页签条里没有与抽屉头重复的「关闭」、Esc 能关、抽屉没把后面的列表吞掉；
- **审核标准（D37）**：审核者详情里看得到标准的名字、正文、允许触发的动作；有标准的不显示
  "审不了任何东西"那条警告；新建表单里执行角色下**不**出现标准栏，切到审核角色才出现，
  且允许的动作是**勾选**（默认只勾最小权限的 `comment.create`）；
- **默认智能体（D36）**：首启就有一个默认；**「默认」徽章有且只有一个**；每个执行者卡片上有
  「设为默认」、审核者没有；点完之后徽章**移到刚点的那张卡**上（原来那个自动让位），界面上
  依然**没有「取消默认」**；布局上开关必须在卡片**里面**、整行与左栏正文都**不许横向溢出**
  （第一版溢出了 54px）；新建任务页的选择器里那一项标着「（默认）」并且**预选的就是它**、
  而且选择器里**只有执行者**。夹具需要**两个执行者**（`run.mjs` 里造，理由见那边注释）；
- **新建任务**：至少不白屏；
- **新建表单 / 设置（右侧抽屉）**：按钮文案是「新建」与「设置」（不是"第一句话设置"）、
  点开后是**贴右边的抽屉**（有遮罩、46rem 宽、**不在主从两栏里**）、关闭后栏头高度**不变**、
  内部没有横向溢出、主操作常驻视口内、Esc 能关；设置抽屉是**分段容器**（`.drawer-section`，
  现在一段：第一句话模版）+ 一个共用的「保存」；段里两个页签（执行 / 审核）**各自独立**、
  填入默认模版真的带变量、**保存真的落库**（直接问接口）、重开看到的就是存下的那份。
  另外钉一条**否定事实**：新建表单里**不该**再有模版那一栏（它是通用配置，不是每个 agent 一份）。

  ⚠️ 这一组是"**位置错了**"这类问题的守卫：面板在左栏里待过两版都不行（一版撑到 736px 横着
  盖住右栏，一版只有 358px 宽、模版编辑器没法用）。还有一条量**输入框的高度**：空的模版
  也得有 300px 以上的下限，填进几十行的那份之后要**跟着长高**（用"内容的行数"兜住这条
  断言，免得框本来就是空的也过）。
  ⚠️ 这一组量的是**容纳关系**（东西在不在它该在的容器里、有没有溢出），不是外观——
  起因见下。

## 三条边界（都是刻意的）

1. **不造 run。** 造 run 就会去调真的 CLI。夹具只有"一条不指派给任何人的任务"，
   所以它验的是**布局与结构**，不是"跑起来之后长什么样"；
2. **数据是确定性的**：一次性 data-dir 首启会播种一对 agent 与一个审核模板，
   断言据此写，不依赖运行者自己的数据；
3. **只写仓库内**：数据、工作目录、Chrome profile、抓回来的 DOM 全在
   `.cache/layout-probe/` 下（跑完留 `report.json` 与 `dump.html` 供排查）。

## 三个坑

- headless Chrome 打完 `--dump-dom` **不会退出**，所以这里是"后台跑 → 轮询输出文件 →
  再杀"，不是"等它结束"。超时可调：`PROBE_TIMEOUT_MS=180000 pnpm run probe:layout`；
- 杀 Chrome 只按**本次专用的 user-data-dir** 匹配。早先用 `pkill -f "Google Chrome"`
  把使用者本人的浏览器一起杀掉过，是个事故——不要写宽匹配；
- **探针里的 `const` 不能重名**。整个内联脚本是一个作用域，重复声明会让**整段脚本**
  语法错误——而症状看起来完完全全是"Chrome 超时"：`dump.html` 里 `#out` 还是
  `pending`，一条 error 都没有（`main()` 里的 catch 根本没机会跑，因为脚本没被解析）。
  加检查时用 `node --check` 过一遍提取出来的脚本，比读 dump 快得多：
  `python3 -c "import re;s=open('tools/layout-probe/probe.html').read();open('/tmp/p.js','w').write(re.search(r'<script>(.*?)</script>',s,re.S).group(1))" && node --check /tmp/p.js`

## 加一条检查

探针（`probe.html`）只上报**量到的事实**，期望值全在 `run.mjs` 的 `CHECKS` 里——"量"与"判"
分开，改期望不必动探针。加检查的步骤：探针里量一个新事实 → `CHECKS` 里加一条 `{view, key,
label, ok}`。

### 一次"看着没坏、其实整垮了"的教训

新建智能体的表单原来渲染在左栏 `pane-head` 里（那个按钮自己管着开不开，表单就画在按钮
旁边）。左栏宽 **416px**，而表单按自己的 `max-width` 画成了 **736px**：横着盖住右栏、
栏头从 167px 涨到 1070px、agent 清单被顶到视口外。**"新建"这个动作把主从布局整垮了。**

而当时代理量了些什么？两栏宽度、卡片内容、选中态、窄屏返回、抽屉……**一条都没红**：
它们没人问"这块东西在不在它该在的容器里、有没有溢出"。补上的就是这一组
（`formInsideHead` / `formFitsPane` / `formOverflowX` / `headGrowthPx` / `varListFitsPane` /
`previewFitsPane`），把表单塞回栏头 + 恢复 `max-width: 46rem` 之后，**5 条同时红**。

所以：**量外观的检查挡不住"位置错了"这类问题**。新加一块界面时，除了"它长什么样"，
还要量"它在谁的里面、有没有越过边界"。

**新加检查后请做一次变异验证**：把对应的实现改坏，确认它真的会红。这个工具自己就抓到过一条
**空过**的检查——"重复字样"那条最初因为表格里一行都没有而永远通过，把「等待审核」塞回模板
照样全绿。
