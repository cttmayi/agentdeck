# 交付前自检清单

逐条打勾，任何一条不通过就不交付。

## 一、能被加载

- [ ] `SKILL.md` 在技能目录**根**上（不是 `src/SKILL.md`、不是 `skill.md`）
- [ ] frontmatter 用 `---` 包围，且是第一段内容
- [ ] `name` 是 kebab-case、≤63 字符、与目录名一致（平台会以它作为 slug）
- [ ] `description` 一句话，**含触发条件**（"当……时用"），不是功能简介
- [ ] `description` 里没有换行（frontmatter 的单行值）

## 二、能被照着做

- [ ] `## When to Use` 写了触发场景**和**不适用场景
- [ ] `## Procedure` 每一步是一次动作，命令/参数完整、可直接复制
- [ ] 需要判断的地方给了**判据**（看到什么算对、看到什么算错）
- [ ] `## Pitfalls` 至少写了一条真实的坑（没有就删掉这一节，别写空话）
- [ ] `## Verification` 给出可执行的验证方式，而不是"检查一下是否正确"

## 三、支持文件

- [ ] 正文引用的每个路径都真实存在，大小写一致
- [ ] 脚本有解释器声明或正文写明调用方式
- [ ] 没有二进制文件、没有 `.git`、没有隐藏文件
- [ ] 总量在限额内（单文件 256 KB / 总计 1 MB / ≤64 个文件）

## 四、内容质量

- [ ] 没有"这次我做了什么"的叙述（那是日志）
- [ ] 没有环境依赖失败、工具吐槽、一次性重试（不结晶清单）
- [ ] 没有未验证的做法
- [ ] 换一个不懂上下文的人照做，能做出同样的结果

## 五、更新场景（进化）额外检查

- [ ] 旧版本里**仍然正确**的部分被保留，没有被"顺手重写"掉
- [ ] 与素材冲突的部分已按素材修正，并在 `Pitfalls` 里记下为什么
- [ ] 被删掉的支持文件确实整个正文都不再引用（删文件要连同引用一起删）
