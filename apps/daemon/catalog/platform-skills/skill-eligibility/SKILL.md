# 配套技能判定

给「智能体生成者」用：判断这份岗位卡该带几条配套技能——是需求里的经验，不是需求本身。

## When to Use

起草配套技能清单时——"这个岗位的做法里，哪些值得沉淀成一条可复用的技能"。

## Procedure

逐条问三个问题：

1. **高频吗**：这个做法是每次干活都会遇到的，还是这次碰巧需要的？
2. **同格式吗**：它的产出有固定形状（格式约定、模版、固定步骤）吗？形状越固定越值得抽。
3. **跨任务可复用吗**：把这个做法写成技能，别的岗位/别的任务用得上吗？

### 值得抽

三个问题里有两个"是"，且它是**做法**（步骤/格式/约定），不是**岗位本身**。

### 不要抽（宁可 0 条）

- **岗位本身**：把岗位职责写进技能 = 把一个岗位复制成两份，改一处就漂。
- **一次性的需求**：这次的具体要求不是经验。
- **硬凑**：判定"没有值得沉淀的做法"是正当结论——配套技能 0 条完全正常，生成智能体不依赖技能也能成立。

### 写法

每条配套技能：`skill/<slug>/SKILL.md`，frontmatter `name` + `description`，正文有 `## When to Use` 与 `## Procedure` 两节。描述写"这个岗位为什么需要它"，不写"它怎么用"（那是正文的事）。
