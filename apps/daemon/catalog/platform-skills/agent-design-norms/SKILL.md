# 智能体设计规范

给「智能体生成者」用：把岗位写成一张能直接生成智能体的岗位卡。

## When to Use

起草 `agent-draft.md` 时——凡是"这个岗位写进岗位卡会是什么样"的取舍，都照这份规范来。

## Procedure

### 1. 岗位卡五字段（缺一不可）

1. **目标**：一句话——这个岗位做什么。
2. **职责**：最常被叫去干的 2–3 件事，动词开头。
3. **边界（不能碰）**：逐条列出禁止事项；**必有**，没有例外。
4. **输出格式**：产出长什么样，有例子就给例子。
5. **验收标准**：怎么算干好了（可检查、可勾选）。

### 2. 指令一段组装

- 生成的智能体只有**一个** `instructions` 字段——所有规则都在这**一段**里，没有第二份文件、没有第二处注入位。
- 段落顺序固定：第一行"你是<岗位名>。"，然后按上面的字段顺序排节。
- 边界节放在显眼处（目标/职责之后、输出格式之前），审阅时人先看到它。

### 3. 角色只有两个取值

岗位卡 `role` 只写 `executor`（干活）或 `reviewer`（审核）。别的角色是平台内置的专属角色，使用者不能自建。

### 4. 验收标准要可检查

"输出要符合要求"是空话；"decisions 每条有 owner + deadline"才算一条标准。写不出可检查的标准，就写"缺关键信息时停下并列出缺什么"这类行为标准。
