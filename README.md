# AgentDeck

一个**跑在自己机器上**的 AI 工作台：把外部的报告 / 事件收进来，让本机的 agent 按**你写的标准**去审核，产出**结构化的判决**——判过了才触发**有界的动作**，判不过就交回执行者重做，直到通过或升级给你。

> 📌 **这份文件是给使用者的**：怎么安装、怎么用、设计理念、你必须知道的风险。
> 给开发者看的在 [`docs/README.md`](./docs/README.md)：代码结构、开发命令、技术选型、不变量。

---

## 设计理念：把「人审」这一关翻过来

主流 agent 产品的流程是 **agent 干活 → 人审 → 人决定 → 人操作**。干活是自动的，但「把关」永远卡在人这里——于是人变成了 **review 队列的管理员**：每天刷一堆「等你批准」的通知，逐条看完再逐条放行。这是这个品类最被诟病的一点。

AgentDeck 把这一关翻了过来：

```
产物进来 → agent 审 → 结构化判决 → 系统执行
```

- **干活**还是 agent（执行者）；
- **审核也交给 agent**——按你写在审核者身上的标准判断；
- 审核产出一个**结构化判决**；
- 判过 → 系统按判决**自动触发动作**；判不过 → 交回执行者**返工重做**（可配次数）；
- 只有 agent 拿不准、确实需要人判断时才升级给你——**人是例外通道，不是默认关卡**。

为了做到这一点，有三个刻意的设计决定：

1. **判决是闭合的。** 结论 / 理由码 / 严重度 / 证据 / 动作都是机器可读的固定取值，只有一处字段留给模型自由发挥。因为**能被程序可靠处置的判断，和一个需要人读的段落，是两种东西**——前者才谈得上自动执行、统计与审计。
2. **审核者 ≠ 执行者，动作只能由判决触发。** 干活的和把关的必须是不同的 agent，agent 之间的链路有深度上限与环检测。这三条是硬不变量，在写库之前强制校验，不会被静默降级。
3. **本地优先。** 工作数据、执行、界面全部在你自己的机器上；远端只承担账号、设定、公共能力目录、第三方查询、记录统计五件事——**不干活，也不持有权威数据**。

## 核心概念（30 秒建立心智模型）

| 概念 | 一句话 |
|---|---|
| **任务**（issue） | 你发起的一件事：填个标题建出来，立刻派给执行者 |
| **执行者** | 干活的 agent——按任务描述产出报告 / 文件 |
| **审核者** | 把关的 agent——按它自己「指令」里的标准判断产出 |
| **判决**（verdict） | 审核产出的结构化结论：结论 / 理由码 / 严重度 / 证据 / 动作 |
| **动作**（action） | 判决**通过**后系统触发的有界操作——全部来自已安装的**工具包**，平台不内置任何动作 |
| **工具包**（tool） | 可安装的「行动」：一个包 = 一组动作，在审核者的「行动权限」里勾上即生效 |
| **技能**（技能） | 可安装的资料 / 方法包：执行者干活时参考什么（它**不**携带审核标准，也不携带动作权限） |
| **工作目录** | 每个任务一个目录，agent 真正的产出都在那里，方便你用 Finder / 终端直接打开 |

## 一条任务的一生

```
你新建一个任务
   │
   ▼
① 执行者干活（产出写到工作目录）
   │
   ▼
② 审核者按标准审核 → 产出结构化判决
   │
   ├─ 通过 ──▶ ③ 触发动作（评论 / 改状态 / 打标签 / 派活…）
   │
   └─ 不通过 ──▶ 交回执行者重做（可配 0–5 次）→ 再审
                    │
                    └─ 次数用完 / 拿不准 ──▶ 升级给你（带结构化原因码）
```

任务清单的**看板**就是这条链的可视化，按「实际进行到哪一步」分六列：**执行中 → 待审查 → 行动中 → 等待人处理 → 已完成审查**（最后一列「已放弃」不在流水线上，只是给放弃掉的任务一个去处）。每一列都是从执行记录**推出来的**，不是人工维护的状态字段——「已完成审查」的意思是「判决已产出且它要求的动作做成了」；「行动中」是动作还在跑，「等待人处理」是判不通过且没有返工可跑（次数用完、或这条任务没配），那是「要你去改」，不是「做完了」。

## 安装

需要 **Node ≥ 22.18**（推荐 24；包管理器用 pnpm）。

> ⚠️ **为什么不是"≥ 22"就够**：这个仓库是**把 `.ts` 直接交给 node 跑**的
> （`pnpm run daemon` 最终是 `node apps/daemon/src/cli.ts`），靠的是 Node 的类型擦除——
> 它从 **22.18** 起才默认可用（23.x 那条线上要 **23.6**）。实测 22.17 会报
> `ERR_UNKNOWN_FILE_EXTENSION: Unknown file extension ".ts"`（加
> `--experimental-strip-types` 也能跑）。分不清就装 Node 24。
>
> 版本不够时不会让你去猜：命令入口前面有一层守卫
> （`scripts/node-entry.mjs`），它会把那段堆栈换成一句能照做的话。

**平台**：macOS / Linux 是第一公民；Windows 可用，但有几处已知缺口
（最要紧的一条：npm 装的 agent CLI 在 Windows 上是 `.cmd` 垫片，而现代 Node 拒绝 spawn
`.cmd`）。装之前先看 [`docs/reference/windows-compat.md`](./docs/reference/windows-compat.md)。

```bash
pnpm install
pnpm run build:web      # ⚠️ 必做一次：界面是构建产物，不进版本库
```

然后按需起下面几个进程：

```bash
# 1) 本机 daemon：托管界面与本地接口（核心，必起）
pnpm run daemon
#    → http://127.0.0.1:4517

# 2) 远端服务（可选）：账号 / 设定 / 公共目录 / 第三方查询 / 记录统计
pnpm run remote
#    → http://127.0.0.1:4518
#      打开根路径就是**管理页**：技能与工具的公共目录
#      —— 能看、能重新同步、能**手动装一条**（填 GitHub 链接）与**卸载一条本地装的**
#      想让那个按钮也走加速器（否则它会用匿名限额去抓）：
#      AGENTDECK_GITHUB_PROXY=https://gh-proxy.com pnpm run remote

# 3) 推荐技能目录的同步工具（可选）：跑一次就退出，抓 GitHub 写进公共目录
pnpm run sync-skills                     # 加 --dry-run 先看会改什么；--refresh 强制重下

# 4) 对外 MCP server（可选，stdio）：让别的 agent 驱动本系统
pnpm run mcp

# 5) 命令行（可选）：人和脚本用。它是 daemon 的客户端，需要 daemon 在跑
pnpm run cli status
```

几点要知道的：

- **`--` 是个坑**：不要写成 `pnpm run daemon -- --port …`——pnpm 会把那个 `--` 一并传给程序，后面所有选项都会被当成位置参数而**全部失效**。所以 daemon 与 CLI 遇到 `--` 都会**直接报错**，而不是静默回落。⚠️ **曾经最阴的一条（2026-10 修掉）**：抓取原来是远端的**子命令**，而 `pnpm run remote -- sync-skills` 里的 `--` 会被 pnpm 原样传进来，于是 `argv[0]` 不是 `sync-skills`、子命令匹配不上——它就**若无其事地把服务起起来**：你要的是同步技能，发生的是跑服务，没有一行说自己理解错了。现在抓取是**独立工具**（`pnpm run sync-skills`，见下面第 3 条），它和 `remote` 各有一道同样的拒绝。
- **顺带把"看不懂的参数"也变成硬错误**：`pnpm run remote` 不做子命令分派，任何它没看懂的 token 从前都会让它继续往下走、最后"服务起来了"——看起来像成功。所以现在两个命令都会**点名拒绝**不认识的参数，并在认得出旧写法时给出新命令：老写法 `pnpm run remote sync-skills` 会被告知改用 `pnpm run sync-skills`（这条命令从前真的会去起服务，实测挂了 300 秒才被外部杀掉，全程没有一行说自己理解错了）。
- **端口是固定的**（4517 / 4518）。被占用时 daemon **大声失败**，不会静默换端口——随机端口意味着「重启后地址变了」，而地址会被写进书签与配置里。
- **两个目录各司其职**：数据目录默认 `~/.agentdeck/data`（可用 `--data-dir` 覆盖），存程序内部状态（SQLite、锁、blob 日志），所以是隐藏的；任务**工作目录**默认在 `~/agentdeck-workspace/`（可用 `--work-root` 覆盖），是 agent 真正的产出，所以放在家目录下、不隐藏，方便你 `cd` 进去。刻意不放在数据目录里面——「产出放在找不到的地方等于没有产出」。
- 常用命令与 CLI 退出码：`pnpm run cli` 默认输出 JSON，退出码 **0** 成功 / **1** 业务失败 / **2** 用法错误 / **3** 连不上 daemon。

### 第一次使用（10 分钟上手）

1. `pnpm run daemon`，浏览器打开 http://127.0.0.1:4517。
2. 进「**智能体**」页，建一个**执行者**（填名称和指令），再建一个**审核者**——审核者的判断依据就写在它的「指令」里，行动权限也挂在它身上（详见下文「界面速览」）。
3. 进「**任务**」页，点顶栏的「**新建任务**」——表单就开在**右边那一栏**（左边的任务清单当参照），填个标题，确认①执行 → ②审核 → ③行动三步的配置，点「创建并派发」。
4. 提交之后右栏自动换成这条新任务的详情，接着看它跑完：执行 → 审核 → 判决 → 动作，一条链走完。
5. 不满意就点裁决区的「**反馈**」接着说——它会接着上一次的会话继续，而不是从头再来。

## 界面速览

侧边栏五项：**聊天 / 任务 / 智能体 / 技能 / 工具**。

| 视图 | 做什么 |
|---|---|
| **聊天** | 和 agent 直接对话——**可以直接动手干活**（读写文件、跑命令，在对话自己的工作目录里），但没有判决契约，也不进审核闭环 |
| **任务** | 一条任务一行：列表 + 详情，或按「实际进行到哪一步」分列的看板；**建任务也在这里**——顶栏的「新建任务」把表单开在**右栏**（清单留在左边当参照），填标题（+ 可选说明）就能建，建完立刻派给执行者，不必再点一次「跑」。窄窗口下表单占满一栏（回列表点侧栏「任务」或顶栏「列表」） |
| **智能体** | 配置执行者 / 审核者：指令、技能、角色、行动权限 |
| **技能** | 安装 / 查看技能（资料 / 方法包） |
| **工具** | 安装 / 查看工具包（可替换的「行动」，平台不内置任何动作） |

### 建任务：一次看清整条链

表单把这一次的**完整链路**摆出来：**① 执行 → ② 审核 → ③ 行动**，三处都可以**只为这一次**临时改，改完都会**提前说清后果**：

- **① 执行**：默认是标了「默认」的那个执行者（在智能体页可设）；还能选**审核不通过时返工几次**（0–5，默认 0 = 不返工、直接交给人）。
- **② 审核**：默认跟随①执行者的「由谁审它」；也可以**只为这一次**换人审，或者这次干脆不审。
- **③ 行动**：默认勾着审核者当前能触发的动作，也可以**只为这一次**改——这次不许它动手，就把勾都取消（长期要改，去智能体页改它的「行动权限」）。勾上的动作还能**钉固定参数**：某几个参数值可以设死，执行时由平台注入、模型不许写。

### 智能体：执行者干活，审核者把关

每个 agent 配指令、技能、角色（执行 / 审核）与它用哪个 CLI。两条关键规则：

- **执行者的「由谁审它」**决定产出会不会被自动审核；「由谁审它」没配 ⇒ 这次不会有审核结论。
- **审核者的「指令」就是它的判断依据**（判断依据与身份是同一件事的两个说法，所以没有单独的「审核标准」一栏）；**「允许触发哪些动作」也写在审核者身上**——点开一个审核者就能看见它按什么判、判完允许动什么。没有写「指令」的审核者拿不到审核任务。
- 每个执行者卡片上还有一个「**设为默认**」——设过之后新建任务默认就交给它。默认只有一个：设成另一个，原来那个自动让位。

### 技能与工具：能力从哪来

- **技能** 是**可安装、带版本与来源、可带支持文件**的资料 / 方法包（执行者干活时参考什么）。来源有四种：本机目录 / GitHub 链接 / 远端目录 / **本地技能目录**（在「设置」里勾选 `~/.claude/skills`、`~/.codex/skills` 这类目录，勾上就持续跟着磁盘走，不必逐条导入）。装技能必须通过「来源里必须有 `SKILL.md`」这一关，缺了当场拒绝。**远端目录那一份是维护者核过的「推荐清单」**（清单在 `tools/skill-catalog-sync/recommended-skills.json`，内容由**独立工具** `pnpm run sync-skills` 从上游抓下来——抓取与远端服务**互不相干**：工具只写一个目录，远端只读那个目录）——装进库里时**来源仍指回它原来那个 GitHub 仓库**（远端是中转，不是出处），带支持文件的技能会**连支持文件一起装**；清单还没同步过时那个页签是空的，界面会明说「远端目录里现在没有条目」。
- **工具包**是**可替换的「行动」**：一个包 = 一个组（一个目录、一份 `tool.json` 清单、一个或多个入口脚本），组内可声明多个动作。**平台不内置任何动作**——判决里引用动作要写成 `<包 slug>.<动作名>`，没在审核者的「行动权限」里勾上、或那个包没装，整条判决都会判为不合规。工具的用法只有一种：**在审核者的「行动权限」里勾上它声明的动作**（审核者只判断不动手；执行者干活时参考的是技能，不是工具）。

更多细节见 [`docs/reference/skills.md`](./docs/reference/skills.md) 与 [`docs/reference/tools.md`](./docs/reference/tools.md)（含一份可以照抄的工具范例 `examples/tools/example-note/`）。

### 跑完之后看的是「最后结果」

执行**中**显示「实时输出」（原始流水）；跑完自动切成「**最后结果**」：

- **左边**：最后那段产出，按 Markdown 渲染（标题、表格、代码块、图片）；
- **右边**：工作目录里的文件，点一下就能打开；
- 「看完整日志」随时能翻回原始的每一条工具调用。

工作目录里的产出文件（`html` / `svg` 之类）打开时是**隔离**的：里面的脚本能跑（所以画布页能真的画出来），但它**读不到**你的数据，也调不动本机接口。

### 不满意就接着说（反馈）

任务详情页的裁决区里有「**反馈**」：执行跑完之后直接写下一步要它做什么，**理由必填**，会**接着上一次的会话**继续，而不是从头再来一遍。三点要知道的：

- 用的是**同一个工作目录**，所以 agent 上次留下的文件还在；
- 会话恢复是**尽力而为**——CLI 拒绝恢复时（换版本、会话过期）日志里会明说「本次没有上文」，不会假装接上了；
- 它是一条**新的 run**（不是给旧 run 追加消息）：一次 run 的产出是不可变快照，往里塞新输入会让「它当时收到了什么」不可回答，审计链也就断了。

### 让 agent 按你的方式开工（第一句话）

交给 CLI 的那段话**可以整段换成你自己写的**。入口在**智能体页左上角「设置」**里的「第一句话模版」——设一次，**所有智能体都生效**。模版是**通用配置**，分执行 / 审核 / 聊天三个页签。

交给 CLI 的东西是三块：**① 框架**（这次 run 的 id / 对象 / 语言 / 挂载的技能 / 你写的护栏与输出要求——来自模版）、**② 身份**（那个智能体自己的「指令」，审核者还要接上它的判断依据）、**③ 任务**（这次要它做的事——平台按这次的事实放）。留空 = 用平台默认那段；写自己的 = ① 整段取代它（默认里「完成后给出一份报告」那类护栏也一并没了，需要自己写进去）。

模版里能用九个变量（`{{runId}}`、`{{subjectType}}`、`{{subjectId}}`、`{{language}}`、`{{skills}}`；审核那份多 `{{reportKind}}`、`{{issueId}}`、`{{previousContext}}`、`{{verdict}}`——其中 `{{verdict}}` 是审核那份**唯一不能省**的，少了它判决格式只能靠猜）。可选内容用 mustache 条件段包裹，没有就整段不出现。点「预览」能看到模版渲染出来长什么样（渲染器与真的那次是同一个，用示例任务，不是你的真实任务）。

### 界面语言与主题

- **语言**：选择器在**「设置」抽屉里**（顶栏右上角的齿轮或账号头像）。切了立刻生效。**只翻界面文字**——判决里的 `pass` / `needs_human`、动作名 `包名.动作名`、状态 `in_progress` 这类**机器读的值一个字都不翻**，它们要在模型、执行器、审计三方之间对齐。所以判决卡片显示成 `needs_human 需要你判断`：值原样，标签跟着语言走。模型的答复语言也跟着走，但已写进库里的日志、通知、历史记录不回译——它们记的是当时发生的事实。
- **主题**：亮色 / 暗色 / 跟随系统（默认），入口也在「设置」抽屉里。切了立刻生效，刷新保持。

## ⚠️ 先读这一段：安全边界

> 它对应需求文档的 `NFR-SEC-01` / `NG7` / `A11`。**它是必读的，不是免责声明。**

| 项 | 事实 |
|---|---|
| **不做沙箱隔离** | 默认情况下，run **以你启动 daemon 的那个 OS 用户的完整权限执行**，可以读写你账户能碰到的任何文件 |
| CLI 权限模式 | 无人值守所必需，因此不弹任何确认 |
| 没有做的事 | 不做文件系统沙箱、不做容器 / microVM、不做凭据代理 |
| 「代码不出本机」的真实含义 | **工作目录不出本机**；但 agent 读写并写进报告 / 判决的内容**会回到远端** |
| 远端管理页 | 远端服务在 **http://127.0.0.1:4518/** 托管控制台（技能 / 工具目录）：能看、能触发重新同步、能手动装一条技能（填 GitHub 链接）与卸载本地装的那条（同步来的要改清单）。它只绑回环；页面上那个"重新同步"按钮会把同步工具当子进程跑（**非回环来源的跨源请求一律 403**），除此之外它不写任何东西 |
| GitHub 加速器（可选） | 国内直连 GitHub 不稳时可加 `--github-proxy <地址>`（如 `https://gh-proxy.com`）让下载走第三方加速器。⚠️ **它是第三方**：能看也能改内容，所以默认不用、只在显式指定时启用，而且**凭证不会交给它**（它自己带凭证，额度 5000/小时） |
| 远端存有什么 | 账号与设定、记录副本；**不含**你的任务正文（prompt / 报告 / 日志——只上报摘要）。⚠️ 例外一处：**公共技能目录**的内容——维护者跑 `pnpm run sync-skills`（独立工具，**不是**远端服务）时，会把推荐清单里那些 GitHub 技能包抓下来，存进**它自己的数据目录**（`<dataDir>/catalog-skills`），既不在代码仓库里，也不经过你的 daemon |

**把 daemon 当作「你自己」来运行。** 它不是一个受限的执行环境。

### 可选沙箱（`--sandbox workdir-write`）

```bash
pnpm run daemon --sandbox workdir-write
```

注意这里**没有** `-- --sandbox`：那个写法会让 `--sandbox` 被当成位置参数而**静默失效**——沙箱根本没开，而你以为开了（见上文「`--` 是个坑」）。

它**只允许写工作目录**，读不受限（agent 本来就要读 CLI 安装位置、`node_modules`、语言工具链）。**它仍然不是安全边界**，请把这句话读完整：

- 它不是容器，也不是 microVM；同一个用户下的其他进程照样能碰到同一个工作目录；
- 它挡的是**这条进程树自己越界**——即 agent 自作主张动了工作目录之外的东西这类意外与误操作；
- 它挡不住一个铁了心要逃逸的对手。macOS 上的 `sandbox-exec` 已被 Apple 标注为 deprecated。

**宁可失败，不可静默降级**：开了沙箱却拿不到工具（`sandbox-exec` / `bwrap`）时，daemon 会**明确报错**，而不是「那就直接跑吧」。静默降级会让你在**以为自己被保护着**的情况下裸奔——那种失败比「功能没做」严重得多，因为它把安全感本身变成了假的。

更彻底的隔离请用**专用 Unix 用户 → 容器 → 独立 VM**。这三种都不在本项目范围内。

## 你的数据去了哪里

远端同步**不经过 daemon**——daemon 不向任何远端发起请求。**页面**同时连着两边，并负责三件事：

| 做什么 | 方向 |
|---|---|
| 定期问远端「有没有待处理项」→ 取回后投给本机 daemon 走审核流程 | 远端 → 页面 → 本机 |
| 把**摘要**（用量、状态）上报到远端 | 本机 → 页面 → 远端 |
| 远端不可达时**本地暂存、恢复后补交** | — |

**上报什么**：只有摘要——执行的用量与状态、任务的状态变更。**不含** prompt 正文、代码、报告原文；摘要只用于去重与统计。远端那份副本是**同步快照，不具证据效力**，权威记录在本机 daemon 里。关闭上报 = 给远端写一条设定 `reportingEnabled: false`（接口 `PUT /api/settings`）。⚠️ **界面上暂时没有这个入口**（2026-10 撤掉了 daemon「设置」抽屉里那几节，D56）；关闭后本机功能**完整可用**，远端整体不可达时同样如此。

**唯一一处 daemon 会主动出网**：从**本地路径 / GitHub 链接**安装技能时由 daemon 自己下载。这条路只允许 https、只允许 GitHub 的几个主机、每一跳跳转都重新校验主机，并限大小 / 文件数 / 超时。它**不涉及 agentdeck 的远端服务**。（这条约束的是 **daemon** 与**页面**。另有两处会出网的东西与它们无关：**同步工具** `pnpm run sync-skills` 抓 GitHub，**远端服务**转发第三方查询——见上表那处例外。）

## 边界与信任模型

1. **浏览器是唯一的远端通道。** 页面由本机 daemon 托管，因此**同源**——跨源那一整套（Origin 白名单、一次性令牌、私有网络预检）都不需要，只剩「只绑回环 + 校验 `Host`」两条。
2. **daemon 不向 agentdeck 的远端服务发起请求。** 它是本机服务，只接收浏览器的操作。远端只承担五件事：账号登录、用户设定、公共 SKILL/TOOL 目录、第三方查询转发、记录统计接收。
3. **审核者 ≠ 执行者，且动作只能由判决触发**，链路有深度上限与环检测。这三条是硬不变量，在写库之前强制校验，不会被静默降级。

```
浏览器页面 ──同源──▶ daemon（界面 + 全部权威数据与本机执行）
     │
     └──跨源──▶ 远端服务（账号 / 设定 / 目录 / 第三方转发 / 统计）
                 ※ 页面直连；daemon 不参与这一跳
```
