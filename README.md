# alpha-helper

一个**跑在自己机器上**的 AI 工作台。它做三件事：

1. 把外部的报告 / 事件收进来；
2. 让本机的 agent 按你写的标准去**审核**，产出**结构化的判决**；
3. 由判决触发**有界的动作**（评论、改状态、打标签、指派 agent）。

判决是闭合的（结论 / 理由码 / 严重度 / 证据 / 动作），只有一处开放字段留给模型自由发挥。
这是刻意的——**能被程序可靠处置的判断，和一个需要人读的段落，是两种东西。**

> 📌 完整规范见 [`docs/`](./docs/README.md)。本文件只讲**怎么跑起来**和**你必须知道的风险**。

## ⚠️ 先读这一段：安全边界

> 这一节对应 `requirements.md` 的 `NFR-SEC-01` / `NG7` / `A11`。**它是必读的，不是免责声明。**

| 项 | 事实 |
|---|---|
| **不做沙箱隔离** | 默认情况下，run **以你启动 daemon 的那个 OS 用户的完整权限执行**，可以读写你账户能碰到的任何文件 |
| CLI 权限模式 | 无人值守所必需，因此不弹任何确认 |
| 没有做的事 | 不做文件系统沙箱、不做容器 / microVM、不做凭据代理 |
| "代码不出本机"的真实含义 | **工作目录不出本机**；但 agent 读写并写进报告 / 判决的内容**会回到远端** |
| 远端存有什么 | 账号与设定、记录副本。远端**不存**任何第三方 payload |

**把 daemon 当作"你自己"来运行。** 它不是一个受限的执行环境。

### 可选沙箱（`--sandbox workdir-write`）

```bash
pnpm run daemon --sandbox workdir-write
```

注意这里**没有** `-- --sandbox`：那个写法会让 `--sandbox` 被当成位置参数而**静默失效**
——沙箱根本没开，而你以为开了。所以遇到 `--` 会直接报错（见上面的说明）。

它**只允许写工作目录**，读不受限（agent 本来就要读 CLI 安装位置、`node_modules`、语言工具链）。

**它仍然不是安全边界。** 请把这句话读完整：

- 它不是容器，也不是 microVM；同一个用户下的其他进程照样能碰到同一个工作目录；
- 它挡的是**这条进程树自己越界**——即 agent 自作主张动了工作目录之外的东西这类意外与误操作；
- 它挡不住一个铁了心要逃逸的对手。macOS 上的 `sandbox-exec` 已被 Apple 标注为 deprecated。

**宁可失败，不可静默降级**：开了沙箱却拿不到工具（`sandbox-exec` / `bwrap`）时，
daemon 会**明确报错**，而不是"那就直接跑吧"。静默降级会让你在**以为自己被保护着**的情况下裸奔——
那种失败比"功能没做"严重得多，因为它把安全感本身变成了假的。

更彻底的隔离请用**专用 Unix 用户 → 容器 → 独立 VM**。这三种都不在本项目范围内。

## 快速开始

需要 **Node ≥ 22**（推荐 24——后端 `pnpm run daemon` 直接跑 `.ts`，无需构建步骤）。

```bash
pnpm install
pnpm run build:web      # ⚠️ 必做一次：Web UI 是 Vite + Svelte 构建产物，不进版本库

# 1) 本机 daemon：托管 Web UI 与本地接口
pnpm run daemon
#    → http://127.0.0.1:4517

# 2) 远端服务（可选）：账号 / 设定 / 公共目录 / 第三方查询 / 记录统计
pnpm run remote
#    → http://127.0.0.1:4518

# 3) 对外 MCP server（可选，stdio）：让别的 agent 驱动本系统
pnpm run mcp

# 4) 命令行（可选）：人和脚本用。它是 daemon 的客户端，需要 daemon 在跑
pnpm run cli status
```

> ⚠️ 不要写成 `pnpm run daemon -- --port …`。pnpm 会把那个 `--` 一并传给程序，
> 而参数解析器见到 `--` 就会把**后面所有选项都当成位置参数**，于是选项全部失效。
> 所以 daemon 与 CLI 遇到 `--` 都会**直接报错**，而不是静默回落。

端口是**固定**的。端口被占用时 daemon **大声失败**，不会静默换端口——
随机端口意味着"重启后地址变了"，而地址会被写进书签与配置里，漂移比端口冲突更难排查。

数据目录默认 `~/.alpha-helper/data`（可用 `--data-dir` 覆盖）——那是**程序内部**状态：
SQLite、锁、blob 日志，所以它是隐藏的。

任务的工作目录默认在 **`~/alpha-helper-workspace/`**（可用 `--work-root` 覆盖）——
那是 **agent 真正的产出**，所以它**在家目录下、不隐藏**，方便你用 Finder 打开或
在终端里 `cd` 进去。刻意不放在数据目录里面：`~/.alpha-helper/data/work/…` 既点开头
又埋两层，"产出放在找不到的地方等于没有产出"。每个任务一个目录
（`<类型>-<id>`，同一个任务的重试会落回同一个目录），目录**根**一改会连带把旧目录搬过去。

### 常用命令

| 命令 | 说明 |
|---|---|
| `pnpm run daemon` | 起本机 daemon（UI + 接口） |
| `pnpm run remote` | 起远端服务 |
| `pnpm run mcp` | 起 MCP server（stdio） |
| `pnpm run build:web` | **构建 Web UI**（clone 之后必做一次；产物在 `apps/web/dist/`，已 gitignore） |
| `pnpm run dev:web` | Web UI 开发模式：Vite dev server（5173）把 `/api` 代理到 daemon，改代码即时热更新 |
| `pnpm run cli <命令>` | 命令行（`status` / `issues` / `reports` / `costs` / `audits-export` …）。默认输出 JSON，退出码 0 成功 / 1 业务失败 / 2 用法错误 / 3 连不上 daemon |
| `node apps/daemon/src/cli.ts --verify-runtime all` | 查看 CLI 版本验证状态（FR-CLI-07），不起服务 |
| `pnpm run check` | typecheck + 全量测试 |
| `pnpm run test` | 只跑测试 |

## Web UI 技术栈

| 层 | 选型 | 为什么 |
|---|---|---|
| 框架 | **Svelte 5** | 编译成很小的原生 JS（产物 89KB / gzip 34KB），**没有运行时框架要下载**——与"daemon 托管静态文件、断网可用"这条约束最合 |
| 构建 | **Vite 6** | 产物输出到 `apps/web/dist/`，daemon 只当它是普通静态文件，不知道 Svelte 的存在 |
| 依赖 | 三个（都在 devDependencies） | 运行时零前端依赖 |
| 样式 | 手写 CSS + **设计令牌层** | 间距（4 的倍数）、字号层级、语义化颜色集中在一处，改主题只改一段 |
| 实时 | 原生 `EventSource`（SSE） | 按 seq 补齐，刷新/重连都不丢消息 |

**为什么不是 Next.js / React**：最初设计文档写的是 Next.js。但它需要 Node 运行时来渲染，
而这里的页面由 daemon 在 `127.0.0.1` 上托管、要能断网工作；一个纯静态产物更贴合。
UI 一直复杂到"需要组件化与路由"才换的——那次切换只动了 `apps/web/`，后端一行没改。

**开发模式**：`pnpm run dev:web` 起 Vite（5173）并把 `/api` 代理到 daemon 的 4517，
所以**浏览器看到的仍是同源**——开发与生产的同源假设一致，不会出现"开发能跑、上线 CORS 炸"。

⚠️ 构建产物**不进版本库**。clone 之后直接起 daemon 会没有界面——这时 daemon 会
明确提示你跑 `pnpm run build:web`，而不是发一个空白页。

## 装 skill

Skills 视图右上角有「安装 skill」，两个来源：

| 来源 | 谁去取内容 | 说明 |
|---|---|---|
| **路径 / GitHub 链接** | daemon | 填本地目录的绝对路径（`/Users/me/dev/my-skill`）或 GitHub 链接（仓库根 / `…/tree/<ref>/<目录>` / `…/blob/<ref>/…/SKILL.md` / Raw 链接） |
| **远端目录** | 页面 | 页面从远端服务取回条目内容再交给 daemon（daemon 不碰远端服务） |

**注入的技能会留在任务的工作目录里。** 跑完之后你可以进工作目录看"它是在什么标准下
干活的"（`.claude/skills/<slug>/SKILL.md`）。去留由一份**落盘的归属清单**对账：
清单里有、这次不挂的会删掉（所以从 agent 上摘掉的技能不会继续生效），清单里没有的同名目录
**绝不覆盖**（那是你自己放的，会直接报错让你改名）。工作目录里的 `CLAUDE.md` 仍然是
**逐字节还原**的——那是你的文件，我们只是临时借用。

**两条路都要过同一关：来源里必须有 `SKILL.md`（大写）。** 技能是靠"把目录摆对"被 CLI
发现的，没有它就永远不会生效——而使用者会以为自己装好了。所以缺了会**当场拒绝**，并把
那个目录里实际有什么列出来，方便改对。大小写不对（`skill.md`）也会单独提醒：macOS 上能
碰巧读到，Linux 上不行。

同目录下的其它**文本**文件会作为**支持文件**一起装上（含子目录，如 `scripts/check.sh`），
运行时和 SKILL.md 一起写进工作目录的 `.claude/skills/<slug>/`。**二进制文件会被跳过并列出来**
——装进来会写坏，所以宁可如实说"没装它"。

**同名不会直接拒绝，而是先比较版本**（远端目录那一页签）：

| 本地 | 目录 | 按钮 |
|---|---|---|
| 没有 | — | 安装 |
| 版本相同 | 同一版 | **已安装**（不可点） |
| 版本更低 | 新版本 | **更新到 x.y.z** |
| 版本更高 | 旧版本 | **退回 x.y.z**（会说清是往回退） |
| 没有版本信息 | — | 替换本地同名（本机自建/从路径装的，无法判断是不是同一份） |

规则本身还是"同名不静默覆盖"：**更新与替换都必须显式确认**，界面上就是那个按钮；
`overwrite` 只在"你明确要动本地已有的东西"时才带上，新装永远不带。
装进来的 skill 与内置的 `general-review` 存在同一个地方（daemon 的本地库）。
内置那份是公共目录里 `general-review` 1.0.0 的本地副本（正文一致），所以首启之后
那一页就会显示「已安装」而不是冲突。

⚠️ 目前**没有卸载**：装了要删只有改库。这是已知缺口。

### 跑完之后看的是「最后结果」

执行**中**显示「实时输出」（原始流水，按 seq 追加）；跑完自动切成「**最后结果**」：

- **左边**：最后那段产出，按 **Markdown 渲染**（标题、表格、代码块、图片），
  产出里引用的图片直接从工作目录显示出来；
- **右边**：工作目录里的文件，点一下就能打开（`.claude/`、`CLAUDE.md` 这些
  平台注入的东西单独归类，不和 agent 的产出混在一起）；
- 「看完整日志」随时能翻回原始的每一条工具调用。

Markdown 渲染器是**自己写的**（`apps/web/src/lib/markdown.ts`）——前端运行时依赖是零，
为一个视图引 `marked` 就把这条约束破了。而它渲染的内容是 **agent 产出的文本**，
页面又与 daemon **同源**，所以"先转义、再拼我们自己的标签"是硬规则：原始 HTML 一律不认、
链接只允许 `http(s)`/`mailto`、图片地址必须经调用方映射。

同样因为同源：工作目录里的文件是 agent 写的，所以文件响应一律带
`Content-Security-Policy: sandbox`（脚本不执行）——否则一个带脚本的 `svg`/`html`
被打开就等于把它变成了操作本机 daemon 的入口。

### 不满意就接着说

任务详情页底部有「**继续沟通**」：执行跑完之后直接写下一步要它做什么，会**接着上一次的会话**
继续（`resumeFromRunId`），而不是从头再来一遍。三点要知道的：

- 用的是**同一个工作目录**（按任务分配），所以 agent 上次留下的文件还在；
- 会话恢复是**尽力而为**——CLI 拒绝恢复时（换版本、会话过期）日志里会明说"本次没有上文"，
  不会假装接上了；
- 它是一条**新的 run**（不是给旧 run 追加消息）：一次 run 的产出是不可变快照，
  往里塞新输入会让"它当时收到了什么"不可回答，审计链也就断了。

## 页面是唯一的远端通道

远端同步**不经过 daemon**——daemon 不向任何远端发起请求（见下面第 2 条）。
所以页面同时连着两边，并负责三件事：

| 做什么 | 方向 |
|---|---|
| 定期问远端"有没有待处理项" → 取回后投给本机 daemon 走审核流程 | 远端 → 页面 → 本机 |
| 把**摘要**（用量、状态）上报到远端 | 本机 → 页面 → 远端 |
| 远端不可达时**本地暂存、恢复后补交** | — |

**上报什么**：只有摘要——执行的用量与状态、任务的状态变更。**不含** prompt 正文、
代码、报告原文；摘要只用于去重与统计。远端那份副本是**同步快照，不具证据效力**，
权威记录在本机 daemon 里。

可以在远端设定里用 `reportingEnabled: false` 关闭上报（FR-REG-16）。关闭后本机功能
**完整可用**；远端整体不可达时同样如此（FR-AUTH-06）。

## 架构要点（三句话）

1. **浏览器是唯一的通道。** 页面由 daemon 托管，因此**同源**——跨源那一整套（Origin 白名单、一次性令牌、私有网络预检）都不需要，只剩"只绑回环 + 校验 `Host`"两条。
2. **daemon 不向 alpha-helper 的远端服务发起请求。** 它是本机服务，接收浏览器的操作。远端只承担五件事：账号登录、用户设定、公共 SKILL/TOOL 目录、第三方查询转发、记录统计接收。
   有一处**刻意的例外**：从**本地路径 / GitHub 链接**安装 skill 时由 daemon 自己下载
   （本地目录路径页面读不到，而"下载到本地"本来就发生在这台机器上）。这条路的边界写死在
   `apps/daemon/src/skill-source.ts`：**只允许 GitHub 的三个主机、只允许 https、每一跳跳转都重新校验主机**，
   并限大小/文件数/超时。它**不涉及 alpha-helper 的远端服务**。要扩到任意 URL 得单独做——
   让本地服务去抓任意地址等于给它一个访问内网的跳板。
3. **审核者 ≠ 执行者**，且**动作只能由判决触发**，链路有深度上限与环检测。这三条是硬不变量，在写库之前强制校验，不会被静默降级。

```
浏览器页面 ──同源──▶ daemon（UI + 全部权威数据与本机执行）
     │
     └──跨源──▶ 远端服务（账号 / 设定 / 目录 / 第三方转发 / 统计）
                 ※ 页面直连；daemon 不参与这一跳
```
