# AgentDeck

一个**跑在自己机器上**的 AI 工作台：让本机的 agent 干活，把「怎么干、按什么顺序干、谁来把关」写成**代码**（编排），人和 agent 都在自己的机器上，产出直接落在你的工作目录里。

> ⚠️ **2026-11 重大改版（D122–D128）**：平台**不再自己攒那套"结论机器"**——智能体组、
> 「执行者 / 审核者」的角色之分、结构化判决、动作能力、返工回路都已退场。要多 agent
> 协作与把关，就在**编排**里写清楚（谁先干、谁来审、不通过就再来一轮）。
> 下面这份说明已按新形态重写；旧版本的历史在
> [`docs/srs/requirements.md`](./docs/srs/requirements.md) §16 的 D122–D128 里。

> 📌 **这份文件是给使用者的**：怎么安装、怎么用、设计理念、你必须知道的风险。
> 给开发者看的在 [`docs/README.md`](./docs/README.md)：代码结构、开发命令、技术选型、不变量。

## 设计理念：把「流程」写成代码，把人留给判断

主流 agent 产品的流程是 **agent 干活 → 人审 → 人决定 → 人操作**。干活是自动的，但「把关」永远卡在人这里——于是人变成了 **review 队列的管理员**。另一类产品反过来：让 agent 自己互相审，但把它们塞进一个"执行者 / 审核者"的角色框架，于是**平台又造了一套结论机器**（结构化判决、理由码、动作权限、返工额度），而这套机器的每一环都要维护，最后变成了新的负担。

AgentDeck 的选择是第三条路：

```
一条任务 → 一个（或一串）agent 干活 → 产出落在工作目录里
                                    ↘ 要人把关？在编排里再派一次
```

- **干活**是 agent——一个智能体就是 agent，不分"执行"还是"审核"；
- **顺序与把关**写在**编排**里：`agent('写作员')` 干完，`agent('审查员', 意见 => …)` 再看，不通过就 `loop` 再来一轮。**编排是代码，可读、可测、可版本管理**；
- **平台不再替你下结论**：没有判决对象、没有动作能力，也就没有"判过了才允许动"这一层；
- 人不是默认关卡，也不是旁观者——他决定要什么、看产出、用「反馈」让它接着改，或者用「放弃」收场。

三个刻意的设计决定：

1. **一个智能体就是 agent。** 没有角色分野（D127）、没有智能体组（D126）。谁干活、谁把关闭，由**这次派谁**和**编排代码**回答，不由平台替你分类。
2. **把关也不特殊。** 要审就再派一条普通 run——它的任务书里写着"审核下面这份产出"，它的答复就是答复。没有第二种 run 形状，也就没有第二套收口逻辑要维护（D125/D128）。
3. **本地优先。** 工作数据、执行、界面全部在你自己的机器上；远端只承担账号、设定、公共能力目录、记录统计——**不干活，也不持有权威数据**。

## 核心概念（30 秒建立心智模型）

| 概念 | 一句话 |
|---|---|
| **任务**（issue） | 你发起的一件事：填个标题建出来，立刻派给一个智能体 |
| **智能体**（agent） | 一个 AI 协作者：指令（它是谁、按什么做事）+ 技能 + 用哪个 CLI。**不分执行与审核** |
| **run** | 一次执行记录：起一个 CLI、喂第一句话、收产出。任务的每一次「干活」都是一条 run |
| **编排**（workflow） | **把流程写成代码**：顺序、循环、并行、谁来把关。多 agent 协作与判定都在这里，见 [`docs/reference/orchestration-api.md`](./docs/reference/orchestration-api.md) |
| **技能**（skill） | 可安装的资料 / 方法包：agent 干活时的参考与支持文件 |
| **记忆**（memory） | 一个 agent 攒下来的经验，按预算带进下一次上下文 |
| **工作目录** | 每个任务一个目录，agent 真正的产出都在那里，方便你用 Finder / 终端直接打开 |

## 一条任务的一生

```
你新建一个任务
   │
   ▼
① 一个智能体干活（产出写到工作目录）
   │
   ├─ 要人把关？→ 在编排里再派一次：把产出交给另一个智能体看，
   │                不通过就 loop 再来一轮（轮数与判定都写在代码里）
   │
   └─ 跑完 ──▶ 你看结果
                 │
                 ├─ 满意 ──▶ 收工（还可以「沉淀技能」，把这套经验写成 skill）
                 └─ 不满意 ─▶ 「反馈」：一句话接着说（同一目录、续上一次会话）
                              或者「放弃」：不再盯它
```

任务清单的**看板**按「实际进行到哪一步」分两列：**进行中 → 已结束**（已完成为一档、"失败"与"已放弃"也在这一列，但长得不一样）。每一列都是从执行记录**推出来的**，不是人工维护的状态字段。

## 安装

需要 **Node ≥ 22.6**（推荐 24；包管理器用 pnpm）。

> ⚠️ **为什么不是"≥ 22"就够**：这个仓库是**把 `.ts` 直接交给 node 跑**的
> （`pnpm run daemon` 最终是 `node apps/daemon/src/cli.ts`），靠的是 Node 的类型擦除——
> 它是 **22.6** 才加进来的，且从 **22.18** 起才**默认**可用（23.x 那条线上要 **23.6**）。
> 低于 22.6 会报 `ERR_UNKNOWN_FILE_EXTENSION: Unknown file extension ".ts"`。
>
> **22.6–22.17（以及 23.0–23.5）不用你操心**：命令入口前面有一层守卫
> （`scripts/node-entry.mjs`），它发现这个 node 没默认开类型擦除，就**自动带上
> `--experimental-strip-types` 重跑一层**（`pnpm run <命令>` 自己传不了 flag，所以
> 这件事只能在这一层做）。它会往 stderr 说明一句"已自动带 flag 重跑"，不是静默适配。
> 实测（真 Node 22.17.0）：改前是那段 `ERR_UNKNOWN_FILE_EXTENSION`，改后 `pnpm run daemon`
> 与 `pnpm run test` 都跑得通。
> 真的低于 **22.6** 时才没辙——那种 node 连那个开关都没有，守卫会如实劝你升级。

**平台**：macOS / Linux 是第一公民；**Windows 已按 2026-10 的兼容性审计修过**
（原本最要紧的一条是"npm 装的 agent CLI 在 Windows 上是 `.cmd` 垫片，而现代 Node 拒绝
spawn `.cmd`"——现在平台会自己把垫片解开，参数不经 shell）。
⚠️ 但那台审计机器是 macOS：**"在真 Windows 上跑一遍"这件事还没做**。
装之前先看 [`docs/reference/windows-compat.md`](./docs/reference/windows-compat.md)
（「现在的状态」+「下一步」两节），那里也说清了**哪些结论已经量到、哪些还只是判断**。

```bash
pnpm install
pnpm run build:web      # ⚠️ 必做一次：界面是构建产物，不进版本库
```

然后按需起下面几个进程：

```bash
# 1) 本机 daemon：托管界面与本地接口（核心，必起）
pnpm run daemon
#    → http://127.0.0.1:4517

# 2) 远端服务（可选）：账号 / 设定 / 公共目录 / 第三方查询 / 记录统计
pnpm run remote
#    → http://127.0.0.1:4518
#      打开根路径就是**管理页**：技能的公共目录
#      —— 能看、能重新同步、能**手动装一条**（填 GitHub 链接）与**卸载一条本地装的**
#      想让那个按钮也走加速器（否则它会用匿名限额去抓）：
#      AGENTDECK_GITHUB_PROXY=https://gh-proxy.org pnpm run remote

# 3) 推荐技能目录的同步工具（可选）：跑一次就退出，抓 GitHub 写进公共目录
pnpm run sync-skills                     # 加 --dry-run 先看会改什么；--refresh 强制重下

# 4) 对外 MCP server（可选，stdio）：让别的 agent 驱动本系统
pnpm run mcp

# 5) 命令行（可选）：人和脚本用。它是 daemon 的客户端，需要 daemon 在跑
pnpm run cli status
```

几点要知道的：

- **`--` 是个坑**：不要写成 `pnpm run daemon -- --port …`——pnpm 会把那个 `--` 一并传给程序，后面所有选项都会被当成位置参数而**全部失效**。所以 daemon 与 CLI 遇到 `--` 都会**直接报错**，而不是静默回落。⚠️ **曾经最阴的一条（2026-10 修掉）**：抓取原来是远端的**子命令**，而 `pnpm run remote -- sync-skills` 里的 `--` 会被 pnpm 原样传进来，于是 `argv[0]` 不是 `sync-skills`、子命令匹配不上——它就**若无其事地把服务起起来**：你要的是同步技能，发生的是跑服务，没有一行说自己理解错了。现在抓取是**独立工具**（`pnpm run sync-skills`，见下面第 3 条），它和 `remote` 各有一道同样的拒绝。
- **顺带把"看不懂的参数"也变成硬错误**：`pnpm run remote` 不做子命令分派，任何它没看懂的 token 从前都会让它继续往下走、最后"服务起来了"——看起来像成功。所以现在两个命令都会**点名拒绝**不认识的参数，并在认得出旧写法时给出新命令：老写法 `pnpm run remote sync-skills` 会被告知改用 `pnpm run sync-skills`（这条命令从前真的会去起服务，实测挂了 300 秒才被外部杀掉，全程没有一行说自己理解错了）。
- **端口是固定的**（4517 / 4518）。被占用时 daemon **大声失败**，不会静默换端口——随机端口意味着「重启后地址变了」，而地址会被写进书签与配置里。
- **几个目录各司其职**：数据目录默认 `~/.agentdeck/data`（可用 `--data-dir` 覆盖），存程序内部状态（SQLite、锁、blob 日志、技能**索引**），所以是隐藏的；任务**工作目录**默认在 `~/agentdeck-workspace/`（可用 `--work-root` 覆盖），是 agent 真正的产出；技能**正文**默认在 `~/.agentdeck/skills/`（可用 `--skills-root` 覆盖）。后两者是你要去翻、去改的东西，所以放在家目录下、不隐藏，方便你 `cd` 进去。刻意不放在数据目录里面——「产出放在找不到的地方等于没有产出」。
- 常用命令与 CLI 退出码：`pnpm run cli` 默认输出 JSON，退出码 **0** 成功 / **1** 业务失败 / **2** 用法错误 / **3** 连不上 daemon。

### 第一次使用（10 分钟上手）

1. `pnpm run daemon`，浏览器打开 http://127.0.0.1:4517。
2. 首启已经给你播了一个智能体「助手」（只有它在的时候不用建）。要新建就在「**智能体**」页点「新建」：填名称与指令——**指令是它的一切**（它是谁、怎么干活、按什么标准判断）。
3. 进「**任务**」页，点顶栏的「**新建任务**」——表单就开在**右边那一栏**（左边的任务清单当参照），写要做什么、选交给谁，点「创建并派发」。
4. 提交之后右栏自动换成这条新任务的详情，接着看它跑完，跑完自动切成「最后结果」。
5. 不满意就点裁决区的「**反馈**」接着说——它会接着上一次的会话继续，而不是从头再来。
6. 想让它**按固定流程多步跑、或者让另一个 agent 把关**：去「**编排**」页写一段代码（`agent(...)` / `loop(...)` / `parallel(...)`），见 [`docs/reference/orchestration-api.md`](./docs/reference/orchestration-api.md)。

## 界面速览

侧边栏：**聊天 / 任务 / 智能体 / 技能 / 沉淀 / 定时任务 / 编排**（+ 设置 / 关于）。

| 视图 | 做什么 |
|---|---|
| **聊天** | 和 agent 直接对话——**可以直接动手干活**（读写文件、跑命令，在对话自己的工作目录里） |
| **任务** | 一条任务一行：列表 + 详情，或按「实际进行到哪一步」分列的看板；**建任务也在这里**——顶栏的「新建任务」把表单开在**右栏**（清单留在左边当参照），填标题选个人就能建，建完立刻派出去，不必再点一次「跑」 |
| **智能体** | 配置 agent：指令、技能、记忆、用哪个 CLI。平台自带几条**内置岗位**（沉淀起草者 / 生成智能体 / 整理记忆等），它们不可删、不可改 |
| **技能** | 安装 / 查看技能（资料 / 方法包） |
| **沉淀** | 把一次跑成功的经验**写成 skill**（起草 → 你改 → 入库），或者顺手生成一个新智能体 |
| **定时任务** | 到点自动派活：cron + 任务模板 + 选一个智能体 |
| **编排** | **把流程写成代码**（顺序 / 循环 / 并行 / 谁来把关）+ 这个编排的历史。编排跑起来的每一次都是一条**任务**，在「任务」页里按编排分组列着，点开就是运行画面 |

### 建任务：只问两件事

- **要做什么**（一个多行框，第一行当标题，其余进说明）；
- **交给谁**（选一个智能体；默认是标了「默认」的那个）。

### 智能体：一个 agent 就是 agent

每个 agent 配指令、技能、记忆与它用哪个 CLI。

- **「指令」是它的一切**：它是谁、怎么干活、按什么标准判断——都写在这一栏里（判断依据与身份本来就是同一件事的两个说法）。
- 不再有"执行 / 审核"的角色选择（2026-11 退场）：想让它把关，就在**编排**里把"请你审核下面这份产出"派给它。
- 每个卡片上有一个「**设为默认**」——设过之后新建任务默认就交给它。默认只有一个：设成另一个，原来那个自动让位。
- 平台自带的几条是**内置岗位**（起草者 / 生成智能体 / 整理记忆 / 沉淀审核者）：不可删、不可改，因为它们干的是平台自己的活。

### 技能：能力从哪来

- **技能** 是**可安装、带版本与来源、可带支持文件**的资料 / 方法包（agent 干活时参考什么）。来源有三种：本机目录 / GitHub 链接 / 远端目录。装技能必须通过「来源里必须有 `SKILL.md`」这一关，缺了当场拒绝。**远端目录那一份是维护者核过的「推荐清单」**（清单在 `tools/skill-catalog-sync/recommended-skills.json`，内容由**独立工具** `pnpm run sync-skills` 从上游抓下来——抓取与远端服务**互不相干**：工具只写一个目录，远端只读那个目录）——装进库里时**来源仍指回它原来那个 GitHub 仓库**（远端是中转，不是出处），带支持文件的技能会**连支持文件一起装**；清单还没同步过时那个页签是空的，界面会明说「远端目录里现在没有条目」。安装面板还有另外两个页签：「**从本地安装**」扫 `~/.claude/skills`、`~/.codex/skills` 这类目录，把里面发现的技能列出来**逐条装**（装完就是一条普通技能，**不**自动跟着源目录走）；「**本地清单**」读的是仓库自带的一份 JSON（`apps/daemon/catalog/skills.json`），每条写一个**安装方法**（GitHub 链接或本地路径），界面**按类别分组、默认折叠**列出来（点类别标题展开那一组，再点某条右侧的按钮装）——**不用远端服务、不用同步工具、不用登录**（起 daemon 时用 `--skills-catalog <路径>` 可以换一份）。装进来的技能**正文与支持文件存成真文件**，落在 `~/.agentdeck/skills/<slug>/`（`--skills-root` 可覆盖），**改那里的 `SKILL.md` 就生效**（磁盘为准）；来源与版本这类索引留在数据目录的 `log/skill.jsonl` 里。**所有来源都一样、没有例外**——从本地技能目录装进来的也是复制一份、落盘，装完不再跟源目录走。
- ⚠️ **工具包（可替换的「行动」）已随动作能力一起退场（2026-11，D123）**：平台不再有"判决触发动作"这一层，所以也没有装包的地方。

更多细节见 [`docs/reference/skills.md`](./docs/reference/skills.md)。

想把它当本地能力用（脚本 / 定时任务 / 别的程序里的一步）？见 [`examples/task-api/`](./examples/task-api/)：`curl` 与 node 两种写法，含幂等与异步收口。

### 跑完之后看的是「最后结果」

执行**中**显示「实时输出」（原始流水）；跑完自动切成「**最后结果**」：

- **左边**：最后那段产出，按 Markdown 渲染（标题、表格、代码块、图片）；
- **右边**：工作目录里的文件，点一下就能打开；
- 「看完整日志」随时能翻回原始的每一条工具调用。

工作目录里的产出文件（`html` / `svg` 之类）打开时是**隔离**的：里面的脚本能跑（所以画布页能真的画出来），但它**读不到**你的数据，也调不动本机接口。

### 不满意就接着说（反馈）

任务详情页的裁决区里有「**反馈**」：执行跑完之后直接写下一步要它做什么，**理由必填**，会**接着上一次的会话**继续，而不是从头再来一遍。三点要知道的：

- 用的是**同一个工作目录**，所以 agent 上次留下的文件还在；
- 会话恢复是**尽力而为**——CLI 拒绝恢复时（换版本、会话过期）日志里会明说「本次没有上文」，不会假装接上了；
- 它是一条**新的 run**（不是给旧 run 追加消息）：一次 run 的产出是不可变快照，往里塞新输入会让「它当时收到了什么」不可回答，审计链也就断了。

### 让 agent 按你的方式开工（第一句话）

交给 CLI 的那段话**可以整段换成你自己写的**。入口在**设置页**里的「第一句话模版」——设一次，**所有智能体都生效**。模版是**通用配置**，分「**任务**」「**聊天**」两个页签：**在任务页派活用它（任务）、在聊天页跟它说话用它（聊天）**——定时任务与编排的每个节点也算"派活"，走「任务」那一份。

交给 CLI 的东西是三块：**① 框架**（这次 run 的 id / 语言 / 挂载的技能——来自模版）、**② 身份**（那个智能体自己的「指令」，外加它攒下的记忆）、**③ 任务**（这次要它做的事——平台按这次的事实放）。留空 = 用平台默认那段；写自己的 = ① 整段取代它（想加"完成后给出一份报告"这类要求，就写进那一份里）。

模版里能用五个变量（`{{runId}}`、`{{subjectType}}`、`{{subjectId}}`、`{{language}}`、`{{skills}}`）。可选内容用 mustache 条件段包裹，没有就整段不出现。点「预览」能看到模版渲染出来长什么样（渲染器与真的那次是同一个，用示例任务，不是你的真实任务）。

### 界面语言与主题

- **语言**：选择器在**「设置」抽屉里**（顶栏右上角的齿轮或账号头像）。切了立刻生效。**只翻界面文字**——状态 `in_progress`、阶段名这类**机器读的值一个字都不翻**，它们要在模型、执行器、审计三方之间对齐。值原样，标签跟着语言走。模型的答复语言也跟着走，但已写进库里的日志、通知、历史记录不回译——它们记的是当时发生的事实。
- **主题**：亮色 / 暗色 / 跟随系统（默认），入口也在「设置」抽屉里。切了立刻生效，刷新保持。

## ⚠️ 先读这一段：安全边界

> 它对应需求文档的 `NFR-SEC-01` / `NG7` / `A11`。**它是必读的，不是免责声明。**

| 项 | 事实 |
|---|---|
| **不做沙箱隔离** | 默认情况下，run **以你启动 daemon 的那个 OS 用户的完整权限执行**，可以读写你账户能碰到的任何文件 |
| **任务隔离（引导 + 拦截，2026-10，D76）** | 每个执行 run：第一句话里平台无条件写「任务边界」；claude runtime 还往工作目录注入 **PreToolUse hook**（`.claude/settings.json` + `.agentdeck/hooks/`），`Bash / Read / Edit / Write / Glob / Grep` 的目标路径在工作目录外就 **deny**。**它是隔离，不是沙箱**（NG7 不变）：结构化工具全拦，Bash 只按命令文本拦明显越界（`..` / `~` / 工作目录外的绝对路径）；挡的是"agent 自己越界"这类意外，挡不住铁了心要逃逸的对手 |
| CLI 权限模式 | 无人值守所必需，因此不弹任何确认 |
| 没有做的事 | 不做文件系统沙箱、不做容器 / microVM、不做凭据代理 |
| **本地一次性任务接口**（2026-10，D91） | `POST /api/task`：给一句提示词就跑一次 agent、把结果直接返回（脚本 / 定时任务 / 别的程序里的一步）。它**只从回环够到**（daemon 只 `listen 127.0.0.1` + Host 白名单），输入是**白名单**（只说"干什么"，改不了身份 / env / 技能 / CLI 参数），且**不进 MCP、不加 CLI 命令**。⚠️ **绝不要把它经隧道 / 内网穿透暴露出去**——那样它就是远程代码执行；要对外必须先加 token 与单次预算上限 |
| 「代码不出本机」的真实含义 | **工作目录不出本机**；但 agent 读写并写进回复的内容**会回到远端** |
| 远端管理页 | 远端服务在 **http://127.0.0.1:4518/** 托管控制台（技能目录）：能看、能触发重新同步、能手动装一条技能（填 GitHub 链接）与卸载本地装的那条（同步来的要改清单）。它只绑回环；页面上那个"重新同步"按钮会把同步工具当子进程跑（**非回环来源的跨源请求一律 403**），除此之外它不写任何东西 |
| GitHub 加速器（可选） | 国内直连 GitHub 不稳时可加 `--github-proxy <地址>`（如 `https://gh-proxy.org`）让下载走第三方加速器。⚠️ **它是第三方**：能看也能改内容，所以默认不用、只在显式指定时启用，而且**凭证不会交给它**（它自己带凭证，额度 5000/小时） |
| 远端存有什么 | 账号与设定、记录副本；**不含**你的任务正文（prompt / 报告 / 日志——只上报摘要）。⚠️ 例外一处：**公共技能目录**的内容——维护者跑 `pnpm run sync-skills`（独立工具，**不是**远端服务）时，会把推荐清单里那些 GitHub 技能包抓下来，存进**它自己的数据目录**（`<dataDir>/catalog-skills`），既不在代码仓库里，也不经过你的 daemon |

**把 daemon 当作「你自己」来运行。** 它不是一个受限的执行环境。

### 可选沙箱（`--sandbox workdir-write`）

```bash
pnpm run daemon --sandbox workdir-write
```

注意这里**没有** `-- --sandbox`：那个写法会让 `--sandbox` 被当成位置参数而**静默失效**——沙箱根本没开，而你以为开了（见上文「`--` 是个坑」）。

它**只允许写工作目录**，读不受限（agent 本来就要读 CLI 安装位置、`node_modules`、语言工具链）。**它仍然不是安全边界**，请把这句话读完整：

- 它不是容器，也不是 microVM；同一个用户下的其他进程照样能碰到同一个工作目录；
- 它挡的是**这条进程树自己越界**——即 agent 自作主张动了工作目录之外的东西这类意外与误操作；
- 它挡不住一个铁了心要逃逸的对手。macOS 上的 `sandbox-exec` 已被 Apple 标注为 deprecated。

**宁可失败，不可静默降级**：开了沙箱却拿不到工具（`sandbox-exec` / `bwrap`）时，daemon 会**明确报错**，而不是「那就直接跑吧」。静默降级会让你在**以为自己被保护着**的情况下裸奔——那种失败比「功能没做」严重得多，因为它把安全感本身变成了假的。

更彻底的隔离请用**专用 Unix 用户 → 容器 → 独立 VM**。这三种都不在本项目范围内。

## 你的数据去了哪里

远端同步**不经过 daemon**——daemon 不向任何远端发起请求。**页面**同时连着两边，并负责三件事：

| 做什么 | 方向 |
|---|---|
| 定期问远端「有没有待处理项」→ 取回后投给本机 daemon 走审核流程 | 远端 → 页面 → 本机 |
| 把**摘要**（用量、状态）上报到远端 | 本机 → 页面 → 远端 |
| 远端不可达时**本地暂存、恢复后补交** | — |

**上报什么**：只有摘要——执行的用量与状态、任务的状态变更。**不含** prompt 正文、代码、报告原文；摘要只用于去重与统计。远端那份副本是**同步快照，不具证据效力**，权威记录在本机 daemon 里。关闭上报 = 给远端写一条设定 `reportingEnabled: false`（接口 `PUT /api/settings`）。⚠️ **界面上暂时没有这个入口**（2026-10 撤掉了 daemon「设置」抽屉里那几节，D56）；关闭后本机功能**完整可用**，远端整体不可达时同样如此。

**唯一一处 daemon 会主动出网**：从**本地路径 / GitHub 链接**安装技能时由 daemon 自己下载。这条路只允许 https、只允许 GitHub 的几个主机、每一跳跳转都重新校验主机，并限大小 / 文件数 / 超时。它**不涉及 agentdeck 的远端服务**。（这条约束的是 **daemon** 与**页面**。另有两处会出网的东西与它们无关：**同步工具** `pnpm run sync-skills` 抓 GitHub，**远端服务**转发第三方查询——见上表那处例外。）

## 边界与信任模型

1. **浏览器是唯一的远端通道。** 页面由本机 daemon 托管，因此**同源**——跨源那一整套（Origin 白名单、一次性令牌、私有网络预检）都不需要，只剩「只绑回环 + 校验 `Host`」两条。
2. **daemon 不向 agentdeck 的远端服务发起请求。** 它是本机服务，只接收浏览器的操作。远端只承担五件事：账号登录、用户设定、公共 SKILL/TOOL 目录、第三方查询转发、记录统计接收。
3. **平台的边界在"派活"这一层，不在"替你想"这一层。** 三条硬规矩：派活的人只能是**你 / 定时任务 / 编排**（CLI 与 MCP 都**不提供**"提交任意 run"——那接受任意 `workDir` 并 spawn 子进程，等于开放代码执行入口）；平台**内置岗位**不接业务任务（它们干的是平台自己的活）；**编排是代码**——它跑在受限的 AsyncFunction 里，只有 `agent` / `loop` / `parallel` / `route` / `gate` 几个原语，不能直接碰文件与网络。

```
浏览器页面 ──同源──▶ daemon（界面 + 全部权威数据与本机执行）
     │
     └──跨源──▶ 远端服务（账号 / 设定 / 目录 / 第三方转发 / 统计）
                 ※ 页面直连；daemon 不参与这一跳
```
